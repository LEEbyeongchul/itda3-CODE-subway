## 한 페이지 요약

**한 줄**
> 온라인으로 산 식품은 받기 전까지 소비기한을 볼 수 없다. 셀러가 포장할 때 송장과 제품 뒷면을 한 컷 찍으면, OCR이 판매 페이지의 약속("발송일 기준 N일 이상")과 자동 대조해 미달이면 발송을 막고, 통과하면 실제 기한을 구매자 주문내역에 띄운다.

**왜 이 도메인인가 (3줄)**
1. **규제는 있는데 검증 수단이 없다.** 2023년부터 온라인 식품 페이지에 소비기한 약속을 써야 하는데, 플랫폼 스스로 "수시 입출고라 일일 검토 불가"라고 인정했다.
2. **눈이 닿지 않는 곳이다.** 소비자는 볼 수 없고, 셀러 눈은 수백 SKU의 약속과 대조하거나 주문별 증빙을 남길 수 없다. "그냥 보면 되잖아"가 성립하지 않는 유일한 소비자 접점.
3. **모델 제약이 곧 비용 설계다.** 하루 수십만 장 배치 처리라 CPU 장당 초가 서버 대수다. 대회 채점 조건이 그대로 운영 비용표가 된다.

**기존 안(급식·물류·편의점)과의 차이**
- 셋 다 "기한 지난 걸 걸러낸다"에 머문다. 이 안은 기한을 **소비자에게 보여주는 정보**이자 **규제 준수 증빙**이자 **데이터 자산**으로 바꾼다.
- 셋 다 안내서 FAQ 예시거나 그 인접이라 다른 팀이 고를 확률이 높다. 이 안은 아니다.
- 물류는 박스 단위라 낱개 뒷면 사진(대회 데이터)과 어긋난다. 이 안은 셀러 포장대에서 찍는 낱개 뒷면 사진이라 데이터 분포가 그대로 일치한다.

**솔직한 약점**
- 피해 "규모" 숫자가 없다. 사례는 2020~2022년 기사로 반복 확인되지만 연간 건수·플랫폼 CS 비용은 미확보 → 공공데이터포털 1372 상담 데이터에서 직접 추출 (§9)
- 플랫폼 강제가 없으면 셀러가 찍을 유인은 "분쟁 면책"뿐 → 인센티브 설계로 푼다 (§4)
- 사진 한 장이 "그 주문에 보낸 그 제품"이라는 보장은 없다 → 송장과 한 컷 촬영 규칙 (§2-1)

## 1. 문제: 온라인에서는 소비기한을 사기 전에 볼 수 없다

### 1-1. 무슨 일이 벌어지나

마트에서는 뒤집어 보면 1초다. 온라인에서는 택배를 뜯어야 처음 본다. 그래서 반복되는 일:

| 사례 | 내용 | 출처 |
| --- | --- | --- |
| 분유 | 12만 2천 원에 샀는데 기한 2개월 남은 제품. "상세설명에 기재했다"며 반품 거절 | 소비자가만드는신문 2020.5 |
| 유아주스 | 48개입 구매, 기한 7일 남은 제품 배송 | 소비자가만드는신문 2022.9 |
| 양배추즙 | 20포 9천 원, 기한 5개월 남음. 교환하려니 왕복배송비 6천 원 요구 | 소비자가만드는신문 2022.9 |
| 과자 | "최근 제조일자" 안내와 달리 4개 중 2개가 기한 2주 남음 | 소비자가만드는신문 2020.5 |

소비자고발센터 집계(2020.1~4, 35건): 임박 제품 무안내 판매 45.7%, 기한 경과 제품 22.9%, 기한 미표시 11.4%.

### 1-2. 정부가 만든 규칙

공정위 「전자상거래 등에서의 상품 등의 정보제공에 관한 고시」 개정, **2023-01-01 시행**.
- 온라인 식품 판매 페이지에 소비기한(구 유통기한)을 **반드시** 표시. "실물 상품 참조", "별도 표시"로 대체하던 관행 금지
- 식품은 매일 새 로트가 들어오니 고정 날짜를 못 적는다 → 정부가 허용한 **약속형 표기**:
  - "상품 발송일 기준 소비기한이 △일 이상 남은 상품만 판매"
  - "주문 접수일 기준 △일 이내 제조 상품만 판매"
  - "최소 20XX년 X월 X일 이후까지인 상품만 취급"
- 즉 셀러는 **발송 시점의 잔여기한을 보증**해야 한다.

### 1-3. 그 약속을 아무도 확인하지 않는다 (핵심)

| 주체 | 현실 | 근거 |
| --- | --- | --- |
| 셀러 | SKU 300개, 약속 일수 제각각, 매일 새 로트. 포장할 때마다 "이 SKU 약속이 30일이었나 60일이었나, 오늘 기준 며칠 남았나" 계산 불가 → 손에 잡히는 걸 보낸다 | 구조적 추정 |
| 플랫폼 | "식품은 수시 입출고로 일일 검토가 어렵다" (위메프). "임박 고지는 법적 의무 아니다" (네이버). "페이지 명시 기간과 실제가 다를 때만 무상반품" (티몬) → 그 "다름"을 판정할 수단이 없다 | 소비자가만드는신문 2022.9 |
| 소비자 | 받고 나서야 안다. 따지면 "적어놨다"에 막힌다 | 위 사례 |

> **규칙은 있는데 지키는지 재는 도구가 없다.** 우리 OCR이 그 도구다.

## 2. 해법: 포장대에서 한 컷, 나머지는 자동

### 2-1. 셀러가 하는 일 (딱 하나)

주문 포장 시 송장을 붙인 뒤, **송장 + 제품 뒷면(기한 인쇄면)을 한 컷**으로 촬영. 약 3초.
- 송장이 같이 찍혀야 "그 주문에 그 제품"이 증명된다
- 촬영 단위는 주문당 1컷. 동일 SKU 다수 주문은 로트 단위 1컷으로 축소 가능(운영 옵션)

### 2-2. 서버가 하는 일

```
[셀러 포장대] 송장 + 뒷면 1컷
      ↓
[OCR] 날짜 추출 → year / month / day / final_date   (대회 출력 스키마 그대로)
      ↓ 확신 없으면 NONE
[비교기] 페이지 약속 조회 → 잔여일 = 추출 기한 − 발송일 → 약속 일수와 비교
      ├─ 통과   → 주문에 실제 기한 첨부 → 구매자 앱 "이 상품 소비기한 2026-10-14" 표시
      ├─ 미달   → 셀러 화면 즉시 알림 "약속 30일, 실제 20일" → 다른 로트로 교체 후 발송
      └─ NONE   → 셀러가 그 건만 직접 확인 후 입력 (전수 → 예외만)
```

### 2-3. As-Is / To-Be

| 단계 | 지금 | 도입 후 |
| --- | --- | --- |
| 페이지 약속 | 셀러가 적음 | 동일 (변화 없음) |
| 약속 이행 확인 | 없음 | 발송 전 자동 대조, 미달 차단 |
| 소비자 정보 | 받아야 앎 | 배송 전 주문내역에서 확인 |
| 분쟁 | "적어놨다" vs "못 봤다" 싸움, 배송비 떠넘기기 | 사진·값·시각이 주문에 붙어 있어 즉시 판정 |
| 규제 준수 증빙 | 없음 | 주문별 자동 축적 |
| 사람 확인 | 아무도 안 봄 (0%) | NONE 건만 셀러 확인 (약 10%) |

## 3. "그냥 눈으로 보면 되잖아"에 대한 답

OCR이 눈을 이기려면 읽은 **다음에** 사람이 해야 할 일이 있어야 한다. 이 도메인은 다섯 조건을 모두 통과한다.

| 조건 | 해당 | 설명 |
| --- | --- | --- |
| 타이핑을 대체 | ○ | 주문별 기한을 시스템에 남기려면 셀러가 쳐야 한다. OCR이 대신 친다 |
| 계산을 대체 | ○ | SKU별 약속 일수 조회 + 잔여일 계산. 300건 포장하면서 매번 하는 사람은 없다 |
| 조회를 대체 | ○ | "이 SKU 약속이 며칠이었나"를 페이지에서 찾아야 한다 |
| 증빙을 남김 | ○ | 눈으로 본 건 분쟁에서 쓸모없다. 사진 + 값 + 시각이 남아야 한다 |
| 읽을 사람이 부재 | ○ | 소비자는 제품이 셀러 창고에 있어 아예 볼 수 없다 |

냉장고 앱이 망한 이유는 "이미 손에 든 걸 왜 찍냐"다. 여기는 손에 없어서 찍어야만 한다.

## 4. 도입 유인 (누가 왜 쓰나)

| 주체 | 얻는 것 | 비고 |
| --- | --- | --- |
| **셀러** | ① 찍은 주문은 "임박 아니냐" 반품 요구에 증거 보유 → 배송비 분쟁 면책 ② "실제 소비기한 확인됨" 배지 → 안 찍는 셀러 대비 전환율 | 동작 1개 추가의 대가 |
| **플랫폼** | ① 고시 준수 증빙 자동 축적 ② CS 중재 건수 감소 ③ 식품 카테고리 신뢰도 → 재구매 | 도입 주체. 초기엔 자율, 성과 확인 후 식품 카테고리 의무화 가능 |
| **소비자** | 마트에서 뒤집어 보는 것과 같은 정보를 배송 전에 얻음 | 별도 행동 없음 |
| **규제기관** | 고시가 실제로 지켜지는지 데이터로 확인 | B2G 확장 여지 |

**단계적 도입**: 임박 분쟁이 잦은 카테고리(분유·이유식·즙·건강기능식품)부터 시작 → 성과 지표(분쟁 건수, 반품률) 확보 → 전 식품 확대.

## 5. 모델 설계와의 연결 (심사 논리 포인트)

| 대회 조건 | 서비스 논리 |
| --- | --- |
| **NONE이 정답** (QA #7) | 틀린 날짜를 자신 있게 붙이면 소비자에게 **거짓 보증**. 가장 비싼 오류. 모르면 NONE → 셀러 확인이 가장 싼 오류. 채점 규칙과 서비스 원칙이 같다 |
| **연/월/일 부분점수** (QA #2) | 연·월만 읽혀도 "최소 2026-10 이후"로 약속 대조 가능. 필드별 독립 출력이 서비스에서도 쓸모 있다 |
| **CPU 4코어, 장당 4.8초 예산** (QA #1·#3) | 하루 N만 장 × 장당 초 = 서버 대수. 속도 최적화가 곧 비용 절감 |
| **후보 중 최댓값 선택** (QA #6) | 제조일자·소비기한 혼재 시 서비스도 같은 규칙 |
| **뒷면 폰 사진 3,352장** | 셀러 포장대 사진과 동일 분포. 도메인 이동 없음 |

**정밀도 + 커버리지 두 지표**: "답한 것 중 오답 1% 미만" + "커버리지 90%"면 셀러는 10건만 보고, 나머지 90건은 증빙이 자동으로 붙는다. 지금은 0건이 확인된다.

**교차검증 여지**: 셀러가 페이지에 적은 약속(예: "2026-10 이후")이 사전 정보로 존재 → OCR 결과가 약속 범위를 크게 벗어나면 오독 의심 → 단독 OCR보다 오탐을 구조적으로 줄일 수 있다.

## 6. 운영·비용 구조 (초안, 본선 15점 항목)

- **처리 방식**: 서버 배치. 포장 사진이 업로드되면 큐에 쌓이고 CPU 워커가 순차 처리. 발송 차단은 실시간이 아니라 "포장 완료 → 집하 전" 수 분 내면 충분
- **비용 산식**: 일 처리량(장) × 장당 추론 시간(초) ÷ 86,400 = 필요 vCPU-일. 예: 일 20만 장 × 1.5초 = 30만 초 ≈ 3.5 vCPU-일 → 4코어 인스턴스 1~2대. 장당 4초면 3~4대. **대회 실측 속도를 이 식에 그대로 대입**
- **온디바이스 대안**: 셀러 폰에서 추론하면 서버 비용 0. 단 폰 성능 편차·앱 배포 부담. 초기엔 서버, 대형 셀러는 온디바이스 옵션
- **저장**: 이미지는 분쟁 시효(통상 3개월)까지만 보관, 이후 추출값만 보존
- **확보할 숫자**: 플랫폼 식품 일 주문 건수, 식품 카테고리 분쟁·반품률, CS 건당 처리 비용

## 7. 확장 3단계 (데이터가 쌓이면)

1. **셀러 신선도 등급**: 주문별 실제 잔여기한 → "이 셀러는 평균 잔여기한 80%". 소비자 선택 기준이자 셀러 경쟁 유도
2. **제조사용 제품 나이 데이터**: 소비기한 − 제품별 보관기간 = 제조일. 촬영일과 빼면 "공장에서 소비자까지 며칠". 제조사는 지금 이 숫자를 모른다(유통사가 안 준다). 채널별·셀러별 유통 체류일수 → 제조사에 파는 데이터 상품
3. **리콜 로트 자동 매칭**: 식약처 회수 명령("제조일 X~Y 로트")이 뜨면 해당 로트를 산 구매자에게만 자동 푸시. 현재 국내 회수율 저조

같은 모델을 오프라인으로 되돌리면 급식 검수·물류 입고(기존 아이디어.md)도 4단계로 흡수 가능.

## 8. 반론 대비 (Q&A)

| 반론 | 답 |
| --- | --- |
| 셀러가 굳이 찍겠나? | 찍은 주문은 반품 분쟁 면책 + 신뢰 배지. 플랫폼은 자율 → 의무화 단계 설계 |
| 사진이 그 주문 제품이란 보장은? | 송장과 한 컷 규칙. 송장 번호가 사진 안에 있어야 접수 |
| 푸드QR 오면 필요 없지 않나? | 셀러 창고 제품 대부분은 QR 미부착(중소 제조·수입·농축수산). QR 있으면 QR로, 없으면 OCR로. 도입 주체가 제조사 수천 곳이 아니라 읽는 쪽 하나 |
| 쿠팡 로켓배송은 이미 WMS로 관리하지 않나? | 맞다. 대상은 3P 마켓플레이스 셀러(네이버 스마트스토어 전체, 쿠팡 마켓플레이스). 직매입은 대상 아님 |
| 피해 규모가 작지 않나? | 2025년 온라인 음식료품 거래액 47조. 분쟁률 0.1%만 잡아도 건수는 크다. 정확한 건수는 1372 데이터로 확보 예정 (§9) |
| OCR 정확도가 보증에 쓸 만한가? | 도트매트릭스에서 범용 OCR 55~60%. 그래서 날짜 전용 설계 + NONE + 약속 범위 교차검증. "보증"은 통과 건에만 붙고 NONE은 사람이 본다 |

## 10. 요약서 2p에 들어갈 문장 (초안)

> 온라인 식품은 2023년부터 판매 페이지에 "발송일 기준 N일 이상"이라는 소비기한 약속을 표시해야 하지만, 플랫폼 스스로 "수시 입출고로 일일 검토 불가"라고 인정할 만큼 이행 검증 수단이 없다. 본 아키텍처는 셀러 포장대에서 촬영한 송장+뒷면 1컷에서 소비기한을 추출해 약속과 자동 대조하고, 미달 시 발송을 차단하며, 통과 시 실제 기한을 구매자에게 표시한다. 확신 없는 경우 NONE으로 셀러 확인에 넘기는 설계는 "거짓 보증"이라는 최대 비용 오류를 구조적으로 막으며, CPU 장당 추론 시간은 그대로 서버 대수 산식에 대입된다.
