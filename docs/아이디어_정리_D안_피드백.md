## 1. 가장 큰 문제 — 5-2 와 7장이 서로 부딪친다

| 위치 | 문서의 주장 |
| --- | --- |
| 5-2 | OCR 이 읽으면 라벨의 출처가 "판매자의 말"에서 "제품에 인쇄된 날짜"로 바뀌어 **믿을 만해진다** |
| 7장 | 판매자가 고치면 걸러낼 수 없고, 라벨이 확인된 정보처럼 보여 **거짓 신뢰**를 준다 |

심사위원이 둘을 나란히 보면 "그래서 믿을 수 있다는 건가, 없다는 건가"를 묻는다. 그리고 "OCR 이 읽었으니 믿을 만하다"는 아래 세 가지 때문에 방어하기 어렵다.

- 우리 모델은 직접 찍은 폰 사진 389장에서 절반 정도만 맞혔다 (`results/pred_custom389_2026-09-28.csv`).
- 최종 값은 어차피 판매자가 확인하거나 고친 값이다.
- 날짜 스티커를 붙이면 OCR 은 가짜 날짜를 정확히 읽는다.

## 2. 대안 — "믿게 해 준다"가 아니라 "확인할 수 있게 해 준다"

> 사진만 있으면 근거는 남지만 아무도 확인하지 않는다. **OCR 은 사진과 날짜 칸을 기계가 대조할 수 있게 만든다.**

이 표현은 보증을 약속하지 않으므로 7장과 부딪치지 않는다. 그리고 5-1 에서 탈락시킨 근거 두 개가 되살아난다.

| 5-1 에서 탈락시킨 근거 | 다시 살릴 수 있는 이유 |
| --- | --- |
| "소비기한 사진 필수 업로드만 해도 됨" | 사진에 날짜가 실제로 찍혔는지는 누군가 확인해야 한다. 건강기능식품 게시글이 월 약 2.4만 건인데 전담 모니터링 인력은 5명이다(`docs/D안_추가조사_0928.md` 8절). OCR 없이는 사진 의무가 지켜지는지조차 알 수 없다 |
| "사람 입력 실수를 줄여 줌 — 근거 없음" | 근거가 있다. 우리 팀이 3,352장을 라벨링할 때 사람이 틀린 것이 확인된 것만 23장이다(봉인 500장 7장 + 판정용 2,852장 16장, 오답만 다시 본 값이라 하한). "사람보다 정확하다"가 아니라 **"사람과 모델이 서로 확인한다"** 로 쓰면 자기모순이 아니다 |

서로 확인하는 구조의 실측값: 판매자가 틀리게 넣은 값이 판독값과 우연히 같아 그대로 지나갈 확률은 봉인 500장 평균 0.2%, 폰 사진 0.4% (`notebooks/exp_a1_inject.py`).

서현 보고서 6-4 절도 "OCR 이 있어야 되는 것"을 같은 방향으로 정리했다.

| 얻는 것 | OCR 이 있어야 하나 |
| --- | --- |
| 입력값과 사진의 대조 | 예 |
| 날짜면이 찍혔는지 확인 | 예 |
| 입력 편의, 라벨 축적 | 예 |
| 규제 대응 (게시글마다 판독 기록) | 예 |
| 남은 일수 표시, 검색·정렬, 기한 지난 글 숨김 | 아니오. 날짜 칸만 있으면 된다 |
