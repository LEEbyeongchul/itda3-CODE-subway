# 날짜 해석 규칙 (요약서 2p 삽입용)

> 운영진 확정(9/9): *"모호한 값은 아키텍처 제출물(팀의 후처리 규칙)에 따라 정답 유무를 판단한다."*
> → 아래 규칙이 `predict.ipynb` 파서와 라벨링 도구에 **동일하게** 구현되어 있으며, 검증셋 라벨도 같은 규칙으로 작성됨.
> 근거 수치는 검증셋 800장 라벨(2026-09-10) 기준.

## 1. 출력 정의

| 출력 | 의미 | 근거 |
| --- | --- | --- |
| `YYYY-MM-DD` | 완전한 날짜 | |
| `NONE-MM-DD` | 연도 미표기 (우유 `10.14 09:45`) | 운영진 #7 |
| `YYYY-MM-NONE` | 일 미표기 (일본 `賞味期限 2027.7`, 유럽 `12.2020`) | 필드별 부분점수 (운영진 #2) |
| `NONE` | 날짜 없음 또는 판독 불가 | |

날짜가 여럿이면 **가장 늦은 날짜** (운영진 #6). 표시 없이 하나만 있으면 그것이 소비기한 (운영진 #5).

## 2. 전처리

- 9자리 이상 연속 숫자는 날짜가 아님 → 파싱 전 제거. 품목보고번호(`20130628332176`) 앞 8자리가 완벽한 날짜로 읽히는 것을 차단.
- 연도 허용 범위 **2017~2031**. 라벨 실측 최소 2017(3건), 최대 2030.
- 도트 프린터 날짜는 `'20 2 7 . 0 4.13'` 처럼 조각나 읽히므로(기준선 미인식 211건의 주원인) 숫자·구분자 사이 공백을 지운 텍스트를 **원문과 함께** 파싱한다. 공백 구분 날짜(`30 12 23`)는 원문에서 잡힌다.
- 연도 앞에 잡음 숫자 하나(`'42025.10.09'`)는 허용.

## 3. 패턴 — 3단계 신뢰도, 상위 단계에서 후보가 나오면 하위는 보지 않음

| 단계 | 패턴 | 예 | 해석 | 라벨 비율 |
| --- | --- | --- | --- | --- |
| 1 | `YYYY.MM.DD` (구분자 `.`·`-`·`/`·공백) | `2027.06.26`, `2026 . 10. 29` | 년/월/일 | 66.8% |
| 1 | `YYYYMMDD` | `20270626` | 년/월/일 | 0.3% |
| 1 | `DD.MM.YYYY` | `20/05/2026`, `30.10.2021` | **연도가 뒤면 일/월/년** (운영진 #8) | 9.5% |
| 1 | `YY.MM.DD` / `DD.MM.YY` | `26.06.25`, `19/12/20` | §4 | 13.6% |
| 2 | `DD MM YY` (공백) | `30 12 23`, `02 06 23` | 일/월/년 우선 (유럽식 각인) | 0.3% |
| 2 | `YYMMDD` / `DDMMYY` (6자리) | `250626`, `050926` | 년월일 우선, 안 되면 일월년 | 0.3% |
| 3 | `YYYY.MM` / `MM.YYYY` | `2027.7`, `12.2020` | 일 NONE | 2.6% |
| 3 | `MM.DD` | `10.14` | 연도 NONE | 2.5% |
| 3 | `NN/NN` 두 개 병기 | `EXP:08/22 MFD:08/20` | **월/연도** (수입품) → 2022-08-NONE | 0.3% |
| 1 | 영문 월 이름 | `NOV 29 2021`, `26 MAR 21`, `AUG292020`, `DEC-28-2021` | 4자리→연도, 1~2자리→일 | 3.7% |
| 3 | 영문 월 + 연도 | `NOV 2021` | 일 NONE → 2021-11-NONE | 0.4% |

인식기가 PaddleOCR PP-OCRv5 로 바뀌면서(2026-09-10) 영문자를 항상 읽는다. 별도 재인식 패스는 없다. 대신 영문자 허용으로 숫자가 O/I/S/B 로 읽히는 것을 `fix_confusions()` 가 되돌린다 (2O27 → 2027, 0ct → Oct, 구분자 사이에 홀로 낀 글자 제거).

## 4. 2자리 연도 3숫자 — 가장 모호한 형식의 결정 규칙

`26.06.25` 는 2026-06-25 (년/월/일) 일 수도, 2025-06-26 (일/월/년) 일 수도 있다.

1. **년/월/일 우선.** 국내 상품 관행. 라벨 실측: 점(`.`) 구분 72 : 5.
2. 년/월/일로 읽은 연도가 **범위(2017~2031) 밖**이면 일/월/년. (`16.02.21` → 2021-02-16, `02/12/22` → 2022-12-02)
3. 년/월/일로 읽은 연도가 **2028 이상**이고 일/월/년도 성립하면 일/월/년. (`28/02/22` → 2022-02-28, `30/07/26` → 2026-07-30). 라벨 800장 중 2028+ 는 4건뿐이라 기대값상 유리.
4. **공백 구분**은 일/월/년 우선 (`30 12 23` → 2023-12-30). 유럽 각인 관행.
5. 구분자(점·슬래시·하이픈)는 순서를 결정하지 않는다. 라벨 실측: 슬래시 일/월/년 7 : 년/월/일 7.
6. 이미지 어디든 **일먼저 키워드**(`BBD`, `BBE`, `BEST BEFORE`, `EXP`, `USE BY`, `DD/MM`)가 읽히면 일/월/년. 라벨링에서는 같은 단서를 보고 `d` 태그를 붙이므로 라벨과 정합. 운영진 #9 "생산지별 해석은 실력 요소" 에 대한 근거 있는 규칙.

미국식 월/일/년(`02/01/25` = 2월 1일)은 **지원하지 않는다.** 라벨 800장 중 1건이며, 지원하면 유럽식(11%)과 정면충돌해 손실이 더 크다.

## 5. 두 숫자 — 월.일 vs 월/연도

| 상황 | 해석 | 근거 |
| --- | --- | --- |
| 점 구분 `10.14`, 시각 동반 | **월.일** → `NONE-10-14` | 라벨: 점 구분 두 숫자 14/14 전부 월.일. 시각은 일 단위 스탬프에만 붙음 |
| 첫 숫자 ≥ 13 (`25.11`) | 연도.월 → `2025-11-NONE` | 월일 수 없음 |
| `NN/NN` 둘 이상 병기, 뒤 숫자가 전부 연도 범위 | **월/연도** | `EXP:08/22 MFD:08/20` (미국 제품) |
| 단독 `07-21` (영문 수입품) | 월.일로 읽음 — **알려진 한계** | 글자만으론 구별 불가. 시각·제품·키워드 문맥이 필요 |

## 6. NONE 정책

- 후보가 0개면 `NONE`. 부분점수 채점에서도 사전확률 날짜를 찍지 않는 이유: `NONE` 이 정답 값으로 존재하고(연도 없음 2.5%, 일 없음 3.3%), 검증셋으로 비교 시 결정.
- 서비스 관점(물류 검수)에서는 신뢰도 임계값으로 `NONE` 비율을 올려 "확신 없으면 사람에게" 로 운용 — 같은 파이프라인, 상수 하나 차이.

## 7. 라벨링과의 정합

- 라벨링 도구(`notebooks/label.py`)의 `normalize()` 가 위 규칙의 정본. `predict.ipynb` 의 `parse_dates()` 는 같은 규칙에 §4-6 키워드 규칙을 더한 것이며, 셀 실행 시 자가검증(assert)으로 위 예시들을 확인한다 (2026-09-10 정합 완료). 라벨 CSV 의 `raw`(포장에 보이는 그대로)에서 나머지 열을 재계산할 수 있으며, 800행 전부 재현 확인(2026-09-10).
- 팀원이 이미지를 보고 규칙과 다르게 판단한 경우는 `d`(일 먼저) 태그 또는 4자리 연도로 명시해 raw 자체가 모호하지 않게 했다.
