### 2.1 B 단계 원인 (이미지로 확인)

세 장(000509·000274·000635)을 크롭 해상도별로 재인식해 확인한 것. 선택 규칙("가장 늦은 날짜")은 문제 없고, **소비기한 후보가 선택 단계까지 못 간다.**

1. **점 탈락**: 도트 프린터 `26.09.01` 을 원본 크롭에서 다시 읽으면 어느 해상도에서든 `26 09 01`. 공백 구분은 규칙상 일/월/년 → 2001년 → 폐기. 640px 전체 인식에서만 점이 뭉개져 살아남는다. 해상도를 올리면 오히려 나빠진다.
2. **이웃 글자 접합**: 원본·1024px 크롭은 `26.03.025`(로트 문자가 붙음)로 파싱 실패, 640px 크롭만 `26.03.02 A5`. 2패스 다수결에 640 표가 없다.
3. **두 줄 한 박스**: 탐지기가 `2025.08.22부터 / 2026.02.21까지` 두 줄을 박스 하나로 잡아 인식기가 한 줄만 읽음. 이건 후보 영역을 원본 해상도로 재탐지해야 갈라진다.

### 2.2 오늘 실험: "2패스는 교정만, 삭제는 금지" (`notebooks/exp_p2keep.py`)

2패스 결과에 같은 연·월 후보가 없으면 1패스 후보를 남긴다. 병기 349장 전체에서:

| 구성 | 정답 | 회복 / 퇴보 |
| --- | --- | --- |
| 현재 (동결본 출력 재현 확인) | 228 (65.3%) | |
| **유지 규칙** | **248 (71.1%)** | **+22 / −2** |
| 유지 규칙 + 공백 `YY MM DD` 연도우선 보조 | 247 | +23 / −4 → 기각 |

회복 22장은 전부 "제조일자(2025-09-xx) → 소비기한(2026-xx-xx)"으로 바뀐 것. 퇴보 2장은 1패스 잡음 후보(2020-02-10 류)가 되살아난 것. **비병기 3,003장 퇴보 검사 (9/22 오후 완료): +29/−4.** 합쳐서 3,352장 **82.0% → 83.4%** (+51/−6). 퇴보 6장 중 3장은 2028년 잡음 후보(003307·001116·002866)가 되살아난 것이라, "유지 후보는 연도 < 2028" 로 좁히는 안을 측정해 볼 만하다(단 000355 는 정답이 2028). predict.ipynb 에 `ITDA_P2_KEEP` 플래그로 구현, 기본 꺼짐. 결과 `results/exp_p2keep_rest_2026-09-22.csv`.

## 4. 분담

코드가 겹치지 않게 **파이프라인 단계**로 나눈다. 서현은 후보가 생긴 뒤(2패스·선택·인식기), 병철은 후보가 생기기 전(탐지·해상도·전처리).

### 4.1 서현 — "읽었는데 틀림" (B 111 + A 19 + C 290)

코드 영역: `pass2`, `select_date`, `parse_dates`, 인식기 로드. 브랜치 `seohyun-final`.

1. **유지 규칙 채택 판정** (1일): 비병기 3,003장 퇴보 검사 → 퇴보가 회복의 1/3 이하면 채택, env `ITDA_P2_KEEP`. 퇴보 원인(1패스 잡음 후보)을 보고 "1패스 후보 유지는 완전한 날짜(연·월·일)이고 등급 1일 때만"으로 좁히는 안도 같이 잰다.
2. **2패스 다수결에 640px 표 추가** (반나절): 지금 표는 (1패스 값, 원본 크롭, 1024 크롭). 640 크롭을 넷째 표로. B 단계 "이웃 글자 접합" 유형.
3. **A 단계 규칙** (반나절): 같은 원문에서 나온 후보끼리는 원래 해석(연/월/일)이 유효하면 일/월/년 해석 후보를 만들지 않는다. 19장 중 DMY4 12장이 대상.
4. **파인튜닝 인식기를 2패스 전용으로** (2일): 1순위로 쓰면 −37장이었던 이유는 날짜가 아닌 줄(로트·시각)에서 날짜를 지어내기 때문. 1패스는 사전학습으로 후보 줄을 찾고, **2패스 크롭 재인식만 파인튜닝 인식기**로 하면 그 부작용이 없다. 전체 라벨 가중치(`코랩_파인튜닝/itda_en_rec_infer_full.zip`, 크롭 정확도 89.8%)를 쓴다. 다수결 표로 넣을지 단독으로 쓸지 둘 다 측정. C 단계 290장의 주 무기.
5. 여유가 있으면: 병기에서 `까지`/`소비기한` 한글 키워드 재인식 (후보 2개 이상일 때만).

### 4.2 병철 — "아예 못 읽음" (D 183 + B 의 "두 줄 한 박스" + small 전체)

코드 영역: `pass1`, `detect`, `ocr_prioritized`, `resize_long`, 도트 폴백. 브랜치 `byeongchul-final`. Colab 학습 담당.

1. **후보 영역 원본 해상도 재탐지** (1일): 1패스 후보 줄 주변을 원본에서 넉넉히 잘라 탐지기를 한 번 더 돌려 줄을 가른다. 작은 크롭이라 비용 작음. B 단계 "두 줄 한 박스" 유형과 병기 잔여 오답의 주 무기. 결과 줄은 서현 쪽 2패스에 그대로 넘긴다 (인터페이스: `cands[i]["items"]` 형식 유지).
2. **탐지 파라미터 사다리** (1일): 미검출일 때만 `box_thresh` 0.6 → 0.4, 탐지 입력 960 → 1280, unclip 조정으로 재시도. D 단계 mid·large 92장이 대상. 시간 상한 안에서 측정.
3. **small 전처리** (1일): 긴 변 ≤ 700px 이미지는 2배 업스케일(cv2 INTER_CUBIC 또는 `cv2.dnn_superres` FSRCNN) 후 탐지. 9/10 EasyOCR 실험에선 효과 없었지만 Paddle 탐지기로는 미측정. small 271장 오답이 대상. 효과 없으면 하루 만에 접는다.
4. **탐지기 파인튜닝** (2일, Colab T4): `data/rec_train_v2/manifest.csv` 의 크롭 박스로 날짜 줄 탐지 데이터 생성 → PP-OCRv5 mobile det 파인튜닝. 로트·시각·품목번호를 안 잡게 되면 C 단계 잡음 후보(SP_DMY 20, CMP6 26)도 같이 줄어든다. `docs/파인튜닝_절차.md` 의 rec 절차를 det 로 복제.

### 4.3 같이 지키는 규약

- **측정셋**: 500장(블록 1~5)은 최종 보고용으로 봉인. 튜닝·판정은 **나머지 2,852장** (1장 = 0.035%p). 기준 출력은 `results/pred_all3352_2026-09-12_v6.csv` (동결본과 같은 규칙, 파인튜닝 폴백만 없음). 정본 join 은 `results/join_all3352_v6.csv`.
- **실험 규약**: 실험 하나 = env 플래그 하나(기본 꺼짐) + `docs/실험_기록.md` 한 줄(회복/퇴보/장당 시간). 회복·퇴보는 항상 전체에서 보고, 상대 영역에서 퇴보가 나면 채택 불가.

- **오답 장부**: `results/diag_errors_2026-09-22.csv` 의 `stage` 열로 각자 담당을 고른다. 다음 진단은 `.venv/Scripts/python notebooks/diag_errors.py` (오답 603장 40분).
