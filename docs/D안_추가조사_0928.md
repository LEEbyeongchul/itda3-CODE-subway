## 9. 시연 순서 (제안)

> 발표에서 OCR 을 돌려 보여 줄 때, 6절의 흐름을 화면 순서로 옮긴 것이다. 지금 있는 캡처(`발표/src/img/demo_*.png`)는 모델의 판독 결과이고, 판매자 화면은 아직 없다.

| 순서 | 화면 | 쓸 사진 | 보여 줄 것 | 대응하는 문제 |
| --- | --- | --- | --- | --- |
| 1 | 글쓰기: 날짜면 촬영 | 일반 인쇄 (`demo_plain`, 000005) | 소비기한 칸이 자동으로 채워지고 옆에 날짜 확대본이 뜬다 | 판매자가 손으로 옮겨 적는다 |
| 2 | 같은 화면 | 제조일·소비기한 병기 (`demo_two`, 000007) | 두 날짜 중 늦은 날짜를 소비기한으로 고른다 | 읽기가 아니라 해석이 어렵다 |
| 3 | 같은 화면 | 도트 인쇄 (`demo_dot`, 000749) | 1차에서 못 읽고 재시도로 읽는다 | 도트 인쇄 |
| 4 | 같은 화면 | 못 읽는 사진 (`demo_none`, 000486) | 칸이 빈칸으로 남고 판매자가 손으로 넣는다. 날짜를 지어내지 않는다 | 틀릴 때 안전하게 틀린다 |
| 5 | 판매자가 다른 날짜를 입력 | 1번 사진 | 판독값과 다르면 확대본을 다시 보여 주고 두 값을 기록한다 | 입력값과 사진의 대조 |
| 6 | 게시글 화면 | 1번 사진 | 판매자 사진에서 읽은 날짜, 남은 일수, 날짜면 원본 | 구매자가 확인할 수 없다 |

시연할 때 정할 것:

- **실시간 촬영은 한 장만.** 폰 사진은 32% 가 10초를 넘겼다. 나머지는 미리 재 본 사진으로 한다.
- **인터넷을 끄고 돌린다.** 외부 API 없이 CPU 로 돈다는 것을 그대로 보여 줄 수 있다.
- **못 읽는 사진을 뺄 필요가 없다.** 4번이 설계 원칙을 보여 주는 장면이다.
- 5·6번 화면은 모델 출력에 화면만 입히면 된다. 만들 범위는 팀이 정한다.
