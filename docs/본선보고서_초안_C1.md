## 1. 개괄

### 1-1. 핵심 접근 방식 요약

식품 포장 사진에서 소비기한을 읽는 문제를 **경량 사전학습 OCR + 날짜 해석 규칙 + 못 읽은 사진 전용 재시도**로 풀었다. 채점 조건(4코어 CPU, GPU 없음, 500장 2,500초, 인터넷 차단)이 설계를 정했다. 원칙은 하나다. **틀릴 때 안전하게 틀린다.** 확신이 없으면 날짜를 지어내지 않고 '미인식'으로 답한다. 풀어야 했던 문제와 대응, 측정값은 아래와 같다.

| 문제 | 대응 | 측정값 | 절 |
| --- | --- | --- | --- |
| 설정 실수 한 번이 배치 전체를 틀리게 한다 | 읽기 대신 기대값과 대조 | 오인쇄를 놓칠 확률 한 장당 0.2% | 6-1 |
| 날짜 확인의 주기·방법·기록이 정해져 있지 않다 | 금속검출기 점검 형식을 옮김, 자동 기록 | HACCP 표준 문서 3묶음 확인 | 6-1 |
| 소규모 공장은 검사 장비가 없다 | 폰 + 내부 PC 1대, 오프라인 | 모델 21MB, 서버비 0원 | 6-2 |
| 헛경보가 많으면 사람이 지친다 | 세 장 중 두 장 규칙, 품목 적합성 시험 | 사람 확인 13.8 → 3.5% | 6-2 |
| 포장에 날짜가 아닌 숫자가 많다 | 긴 숫자열 제거, 신뢰 등급 | 시험 문자열 26종 | 3-3 |
| 제조일과 소비기한이 함께 찍힌다 | 늦은 날짜 선택, 주변 재탐지 | 64.9 → 78.3% | 3-3 |
| 도트 인쇄·각인·저해상도 | 못 읽은 사진에만 재시도 | +17/−0 | 3-2 |
| 개발 데이터와 새로 찍은 사진이 다르다 | 직접 찍은 389장으로 따로 측정 | 86.2% 대 52.4% | 4-2 |
| 채점 서버 속도를 모른다 | 시간 예산 가드 | 한도의 55 ~ 79% | 5 |
| 정답 라벨도 틀린다 | 오답 전수 재점검 | 오류 16장 중 11장은 모델이 맞음 | 2-2 |

### 2-2. 라벨링 규칙 정의 및 수행 절차

**규칙을 먼저 문서로 정하고, 라벨링 도구와 모델이 같은 규칙을 쓰게 했다.**

| 구분 | 내용 |
| --- | --- |
| 사람 (수동) | 포장에 찍힌 그대로 입력(`FEB/26/21`, `30 12 23`). 병기는 늦은 날짜, 제조일자만 있으면 `NONE`, 판독 불가 등 태그 9종 |
| 도구 (자동 규칙) | 연도가 뒤면 일/월/년, 2자리 세 개는 년/월/일 우선, 공백 구분은 일/월/년, 영문 월, 연·월만 있으면 `YYYY-MM-NONE` |
| 수행 | 5명이 블록 단위로 분담, 해상도별로 섞어 무작위 배정. 파이프라인은 실행 때마다 도구와 규칙이 같은지 자가검증 |

**정답 라벨도 검증했다.** 오답 446장을 사람이 전부 다시 봤다. 라벨 오류가 16장이었고 그중 11장은 모델이 맞고 사람이 틀린 것이었다. 8장은 숫자 한 글자를 잘못 옮긴 것이다. 점검자가 고친 18장 중 3장도 규칙과 어긋나 다시 바로잡았다. 이 경험은 6절의 운영 설계(사람의 확인도 기록하고 다시 검증한다)로 이어진다.

### 2-3. 전처리 내용

긴 변 640px 로 줄여 읽고 후보가 없을 때만 1,024px 로 다시 읽는다(해상도를 올려도 ±1%p 에 시간만 30~50% 늘고, 480px 로 내리면 53.4 → 6.4% 로 무너진다. 초기 구성 실험). 허용 문자 밖의 글자는 지우지 않고 공백으로 바꾼다(지우면 `2021(3)` 이 `20213` 으로 붙는다). 후보가 없는 사진에만 도트 인쇄용 침식·블러를 건다(500장 +17/−0). 9자리 이상 이어진 숫자는 해석 전에 지운다(품목보고번호 앞 8자리가 날짜로 읽힌다).

## 3. 아키텍처 설계 논리

### 3-1. 전체 파이프라인 아키텍처 구조도

(그림 자리: `docs/img/architecture.png`)

```
사진
 ├─ ① 1차 읽기 (640px)  글자 위치 탐지 → 큰 글자부터 인식. 완전한 날짜를 찾으면 잔글씨 생략
 │      └ 후보 없음 → 1,024px 재시도 → 도트 인쇄 전처리 후 재시도
 ├─ ② 다시 읽기          후보 줄만 원본 해상도로 재인식 → 1차 결과와 다수결
 │      └ [본선] 1차 후보를 지우지 못하게 함 · 글자 상자 넓히기 · 깨진 줄 다시 읽기
 ├─ ③ [본선] 주변 재탐지  후보 줄 옆에 크기 비슷한 숫자 줄이 있을 때만
 ├─ ④ 못 읽은 사진 전용   파인튜닝 인식기 → [본선] 작은 사진은 2배 확대
 ├─ ⑤ 해석·선택          형식 정규화 → 신뢰 등급 → 연도 범위 → 가장 늦은 날짜
 ├─ 시간 예산 가드        예상 소요가 예산을 넘으면 단계를 줄임
 └─ 출력  YYYY-MM-DD / YYYY-MM-NONE / NONE-MM-DD / NONE
```

모델은 탐지기 1개와 인식기 2개, 합쳐 약 21MB 다. 나머지는 규칙이다. 비용이 큰 재시도는 모두 조건부라 사진의 88% 는 재시도 없이 끝난다.

## 4. 모델 선택 근거 및 성능 평가

### 4-1. 비교한 모델·대안과 최종 선택 근거

| 비교 대상 | 결과 | 판단 |
| --- | --- | --- |
| EasyOCR 탐지 + 인식 | 39.1%, 장당 약 5초 | 속도 초과 |

위 표 첫 세 줄의 정확도는 초기 라벨 133장 기준이다.

### 4-2. 날짜 추출 정확도 결과

**검증 방법**: 정답은 팀이 직접 라벨링한 3,352장이고 연·월·일이 모두 같아야 정답이다. 500장은 봉인하고 채택 판정은 나머지 2,852장에서만 했다. 새로 맞힌 장과 새로 틀린 장을 따로 세어 **퇴보가 회복의 1/3 을 넘으면 기각**했다. 임계값을 데이터에 맞추지 않고 구조 규칙만 채택했다.

| 측정 | 완전일치 | 필드평균 | 그 외 |
| --- | --- | --- | --- |
| 봉인 500장 | **86.2%** | **90.8%** | 미인식 3.0%, 답한 것의 정밀도 88.9% |
| ├ 해상도별 | 저 83.7 · 중 89.5 · 고 86.7% | | 병기 51장 78.4% |
| 판정용 2,852장 | **86.7%** | | 병기 78.3% · 비병기 87.7% |
| 직접 찍은 폰 사진 389장 | **52.4%** | 62.8% | 오답 중 미인식 21.9% (모델이 답하지 않은 사진은 88장, 22.6%), 답한 것의 정밀도 66.8% |
| ├ 찍은 사람별 | 44.0 · 44.1 · 52.0 · 69.8% | | 각인 표시 11장 18.2% |

튜닝에 쓴 사진(86.7%)과 쓰지 않은 사진(86.2%)의 수치가 비슷하다. 폰 사진 389장은 도트 인쇄·각인·병기 같은 어려운 유형을 골라 찍은 것이다. 공장의 날짜 인쇄에는 도트 인쇄가 많아 이 조건과 겹친다. 그래서 **6절의 운영 수치는 통과율 약 86% 와 52% 두 경우로 계산했다.**

단계별 효과(판정용): 예선 구성 82.3% → 다시 읽기 규칙 84.3%(+63/−5) → 한국어 인식기 2차 의견 84.7%(+14/−1) → 해석 규칙 4개 86.0%(+39/−2) → 주변 재탐지·확대 재시도·파인튜닝 재시도 86.9%(+25/−1) → 시간 여유를 위해 한국어 인식기를 끈 최종 구성 86.7%.

## 5. 속도·비용 검증

### 5-1. CPU 추론 속도 측정

개발 PC 두 대에서 연산 스레드를 4개로 제한해 쟀다. 코어를 묶지는 않았고, 느린 쪽 값을 기준으로 본다. 2.7초는 단계별 측정(3.0초)에서 한국어 단계를 뺀 환산값이다.

| 구성 | 장당 | 500장 | 한도 대비 |
| --- | --- | --- | --- |
| EasyOCR 탐지기를 쓴 구성 | 5.8초 | 2,905초 | 초과 |
| 예선 제출본 | 3.2초 | 1,595초 | 64% |
| **본선 최종 구성** (개발 PC 1 / 2) | **2.7초 / 4.0초** | 1,370 / 1,985초 | 55% / 79% |

사진의 88% 는 장당 1.8초에 끝나고 재시도까지 간 12% 가 시간의 절반을 쓴다. 단계별로는 1차 읽기 40%, 도트 전처리 재시도 23%, 파인튜닝 재시도 11% 순이다(한국어 단계를 켠 측정).

## 6. 도메인 활용 및 운영 기획

### 6-1. 적용 도메인 및 도입 대상 기업/산업 정의

**중소 식품공장의 출하 전 '날짜 인쇄 확인'.**

| 항목 | 내용 |
| --- | --- |
| 문제 | 날짜 인쇄기는 가동 전에 입력한 값을 다음 확인 전까지 모든 제품에 찍는다. 설정이 틀리면 그 사이 생산분 전체가 틀린다 |
| 사례 | 날짜 오표시 회수: 국내 깐땅콩(2026)·단백질 보충제(2019), 영국 Tesco·Pieminister(2024~2025). 식품안전나라 회수 목록에서 날짜를 사실과 다르게 표시한 건은 2025년 2건, 2026년 9월까지 5건. 공지는 원인을 밝히지 않아, 인쇄기 설정 실수의 비율은 알 수 없다 |
| 빈칸 | 국내 소규모 HACCP 표준기준서는 날짜를 '표시사항 준수' 한 줄로만 적는다. 확인 주기·방법·조치·기록 서식이 없고, 평가도 날짜가 찍혀 있는지만 본다. 국제 민간 규격(BRCGS 6.2.3)은 포장 시작·중간·자재 변경·종료 때의 날짜 인쇄 점검을 요구한다 |
| 대상 | 소규모 해썹 업체 (해썹 적용 기업의 약 81%). 이들에게 인라인 비전 검사 장비가 없다는 것은 가설이다 |
| 대상이 아닌 곳 | 인쇄기를 전산과 연동하거나 인라인 검사를 쓰는 대형 업체 |
| 기존 제품 | 해외에는 핸드 스캐너로 날짜를 찍어 작업 지시와 대조하는 상용 제품이 있다(전용 라인 터미널 필요). 우리 것은 폰과 오프라인 PC 만으로 돌고, 놓칠 확률을 실측했다 |

**읽기가 아니라 대조.** 공장은 정답(제조일 + 품목별 소비기한 일수)을 이미 안다. 모델에게 백지 시험이 아니라 채점을 시킨다. 업계는 이를 읽기(OCR)와 구분해 대조(OCV)라 부른다.

| | 모델 결과 = 기대값 | 모델 결과 ≠ 기대값, 또는 미인식 |
| --- | --- | --- |
| **인쇄가 맞음** | 통과 | 헛경보 → 사람이 한 번 더 확인 |
| **인쇄가 틀림** | **놓침** — 틀린 인쇄를 하필 기대값으로 읽은 경우만 | 정상 탐지 → 출하 보류 |

모델의 실수는 대부분 헛경보로 간다. 그래서 모델을 사람의 판독 정확도와 비교하지 않는다. 놓칠 확률은 기대값을 일부러 어긋나게 넣어 실측했다(어긋남 10가지: 일 ±1·±2, 1주, 월 ±1, 연 ±1, 일·월 뒤바뀜).

| 자료 | 정상 인쇄가 한 장에 통과 | 놓침 (평균) | 가장 나쁜 유형 (연 −1) |
| --- | --- | --- | --- |
| 봉인 500장 | 86.3% | **0.23%** | 0.63% |
| 직접 찍은 폰 사진 389장 | 52.2% | 0.38% | 1.63% |

통과율은 라벨이 완전한 날짜인 사진(474장, 368장) 기준이다.

연 −1 은 병기 제품에서 모델이 제조일을 읽는 경우다. 그래서 병기 품목은 두 날짜를 모두 대조한다. "기대값이 후보 목록 안에 있으면 통과"로 바꾸면 연 −1 놓침이 0.6 → 2.3% 로 늘어 채택하지 않았다.

### 6-2. 운영 아키텍처 설계 (서버 / 온디바이스)

작업자 폰(촬영) + 공장 내부 PC 1대(판독·판정·기록). 서버·클라우드·인터넷 연결이 필요 없다. 모델 21MB, CPU 전용이다.

```
폰 촬영(고정 거치대) → 해상도·흐림 검사(미달이면 재촬영) → 사내망 → 내부 PC 판독
 → 기대값과 대조 → 판정 → 기록(사진·시각·작업자·품목·기대값·판독값·판정·모델 버전)
```

| 설계 | 근거 |
| --- | --- |
| 기대값 = 촬영 시점의 시스템 날짜 + 품목 마스터의 소비기한 일수 | 제조일을 사람이 입력하지 않아, 인쇄기 설정과 기대값이 같은 입력 실수를 공유하지 않는다 |
| 품목 마스터는 등록·승인 2인. 기준일(생산일/포장일)과 기한 단위(일/월)도 등록 | HACCP 제품설명서의 기한 항목을 옮긴다. 전날 생산해 오늘 포장하는 품목, 개월 단위 기한은 기대값이 매번 어긋나므로 품목별로 기준을 정해 둔다 |
| 품목은 제품 바코드로 식별 | 작업자가 품목을 고르면 인쇄기와 같은 실수를 시스템에도 할 수 있다 |
| 가동 시작·품목 전환·인쇄기 수정 직후·자정 이후 + 정기 촬영 | 오류가 몰리는 순간이 예측 가능. 정기 촬영은 기존 금속검출기 점검 때 같은 사람이 |
| 도입 전 품목 적합성 시험 | 품목마다 30장을 찍어 통과율을 잰다. 기준에 못 미치면 촬영 조건을 바꾸거나 대상에서 뺀다 (아래 표의 이유) |
| 확인 화면에 판독값과 기대값을 숨김, 주 1회 틀린 날짜 시험 제품 | 작업자가 보지 않고 확인을 누르는 것을 막는다. 금속검출기 시편 점검과 같은 절차 |
| 출하 여부는 항상 사람 | 시스템은 두 번째 눈이자 기록 장치 |

**판정 규칙.** 진짜 오인쇄는 모든 제품에 같은 틀린 날짜가 찍히고, 판독 오류는 제품마다 다르게 나온다. 첫 장이 기대값과 다르면 다른 제품 두 장을 더 찍어 세 장 중 두 장 이상이 기대값이면 통과시킨다. 여러 장이 같은 틀린 값으로 읽히면 출하를 보류하고, 값이 제각각이면 사람이 실물을 본다.

| 규칙 | 사람 확인 (통과 약 86%) | 사람 확인 (통과 약 52%) | 놓침 | 점검당 추가 촬영 |
| --- | --- | --- | --- | --- |
| 한 장 판정 | 13.8% | 47.8% | 기준 | 없음 |
| 한 장 더, 둘째가 기대값이면 통과 | 1.9% | 22.8% | 약 2배 | 0.14 / 0.48장 |
| **세 장 중 두 장** | **3.5%** | **34.8%** | 거의 같음 | 0.28 / 0.96장 |

`[가정]` 사진 간 판독 오류가 독립이라고 둔 계산이다. **통과율이 낮으면 이 규칙으로도 세 번에 한 번은 사람이 봐야 한다.** 공장의 날짜 인쇄는 도트 인쇄가 많고 이것이 우리 모델의 약점이라, 품목별 통과율을 도입 전에 재는 절차를 설계에 넣었다.

| 구분 | 오류 유형 | 대응 |
| --- | --- | --- |
| 잡음 | 인쇄기 입력 실수, 품목 전환 뒤 이전 설정 유지, 자정 뒤 날짜 미갱신, 인쇄기 시계 오류 | 인쇄 결과가 기대값과 다름 |
| **못 잡음** | 품목 마스터의 소비기한 일수 오등록 | 기대값도 함께 틀린다. 2인 승인으로 예방, 변경 이력으로 영향 기간 특정 |

### 6-3. 예상 운영 비용 산출

라인 1개, 하루 점검 20회, 연 250일, 최저시급 10,320원 기준 `[가정: 촬영 15초, 확인 30초]`.

| 항목 | 통과 약 86% | 통과 약 52% |
| --- | --- | --- |
| 서버·클라우드·라이선스·학습비 | 0원 | 0원 |
| 하루 사람 확인 (세 장 규칙) | 0.7건 | 7.0건 |
| 추가 인건비 — 촬영을 기존 점검에 묶을 때 | 연 약 7.5만 원 | 연 약 36만 원 |
| 추가 인건비 — 촬영을 따로 할 때 | 연 약 29만 원 | 연 약 57만 원 |

하드웨어는 기존 폰과 PC 를 쓰고 거치대는 별도다. 설치·교육·품목 마스터 관리 시간은 포함하지 않았다.

### 6-4. 비즈니스 손실 절감 효과 및 ROI 기획

**계산을 먼저 공개한다.** 연간 이익 = (연간 오인쇄 발생 건수) × (1건당 손실) × (탐지 확률) − 연간 비용.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 업체당 연 발생률 (자릿수만) | 약 0.0012 | 표시 위반 회수 67건 / 5.5년 ÷ 해썹 업체 10,101곳. 분자와 분모의 모집단과 시점이 달라 자릿수만 본다 |
| 판독 단계의 탐지 확률 | 약 99.8% | 놓침 0.23%. 품목 마스터 오등록과 점검 사이 출하분은 포함하지 않음 |
| 손익분기 1건당 손실 | 약 6,300만 원 ~ 3억 원 | 기존 점검에 묶을 때 (연 7.5만 ~ 36만 원 ÷ 0.0012). 촬영을 따로 하면 2.4억 ~ 4.8억 원 |

**기대 손실만으로는 소규모 업체 한 곳의 도입 근거가 약하다.** 이것을 숨기지 않고 가치를 세 가지로 설명한다. ① 소비기한을 연장해 표시하면 1차 위반부터 영업정지와 해당 제품 폐기 대상이 될 수 있다(식품표시광고법 시행규칙 별표 7, 적용 행은 사안에 따라 다름). 소규모 업체에게는 평균이 아니라 존속의 문제이고, 이를 연 수십만 원의 고정비로 대비한다. ② 시각별 판정 기록이 있으면 오류가 뒤늦게 드러나도 회수 범위를 좁힌다. ③ 소규모 업체의 HACCP 평가 지적 1위가 검증관리(27.3%)라 자동 기록이 부담을 던다(정황 근거).

**촬영 주기.** 하루 비용을 최소로 하는 주기는 T* = √(2 × 1회 촬영 비용 ÷ (시간당 오류 발생률 × 시간당 생산액)) 이다. 1회 촬영 43원, 발생률 상한, 시간당 생산액 25만 원(연매출 5억 원 기준)을 넣으면 `[가정: 연 가동 2,000시간]` 가동 시간 기준 약 24시간, 곧 3근무일이 나온다. 정기 촬영을 자주 할 근거는 약하다. 그래서 오류가 몰리는 순간의 이벤트 촬영이 기본이고, 6-3 의 하루 20회는 비용을 넉넉히 잡은 상한이다.
