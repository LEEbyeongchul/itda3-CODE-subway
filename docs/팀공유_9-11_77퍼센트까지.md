## 3. 지금 파이프라인

```
EXIF 보정 → 640px 축소 (없으면 1024px, 그래도 없으면 도트매트릭스 폴백)
 → PP-OCRv5 mobile det 탐지 (5MB) → PP-OCRv5 mobile rec 인식 (8MB), 글자 크기순 8개 배치
 → 2패스: 후보 줄만 원본 해상도로 재인식
 → 후처리: 오독 복원 → 정규식 4단계 → 연도 2017~2031 검증 → 신뢰 등급 → 가장 늦은 날짜
 → YYYY-MM-DD / NONE-MM-DD / YYYY-MM-NONE / NONE
```

구조도: `docs/img/architecture.png`. 날짜 해석 규칙은 `docs/날짜_해석_규칙.md` 정본과 같고, 라벨링 도구와도 동일합니다. **운영진이 모호한 날짜는 팀 후처리 규칙으로 채점한다고 했으므로 요약서 2p 에 이 규칙표를 꼭 넣어야 합니다.**

## 4. 측정 방법 (같은 방식으로 재야 비교가 됩니다)

- 블록 1~5(500장)는 측정 전용. 어떤 튜닝·학습에도 쓰지 않았습니다. 블록 6 이후는 실험용.
- 채택 기준: 실험은 튜닝셋에서, 확인은 500장에서. **회복 수와 퇴보 수를 따로 봅니다.** 300장 기준 ±1%p 는 잡음이라 채택 근거로 안 씁니다.
- 명령: `python notebooks/eval.py --pred <예측csv> --blocks 1-5 --out eval.csv` → 블록·형식·태그·해상도별 정확도와 오답 유형(미검출/전부 틀림/월일 틀림/연도만 틀림).
- 4코어 시뮬레이션: `psutil.Process().cpu_affinity([0,1,2,3])` 로 nbconvert 를 띄우고 `ITDA_THREADS=4`.

## 5. 채점 서버에서 그대로 도는지

- **GitHub Actions 로 Ubuntu + Python 3.10 에서 검증 통과**: `requirements.txt` 만으로 설치 → `download_weights.sh` → 인터넷 차단(죽은 프록시) 상태 Run All → 합성 이미지 3장 정답. 이 브랜치에 push 하면 자동으로 다시 돕니다.
- 발견한 함정: paddleocr 가 강제로 설치하는 비headless OpenCV 는 libGL 없는 Linux 에서 import 가 실패합니다(=0점). `download_weights.sh` 가 headless 예비본을 받아 두고 노트북이 자동 대체하도록 넣었고 CI 에서 확인했습니다.
- 그 외 함정: torch 를 paddle 보다 먼저 import 해야 함(Windows DLL), Paddle 이 torch 스레드를 1로 떨어뜨림(CRAFT 쓸 때), 탐지 모델은 oneDNN 을 꺼야 함(Windows).

## 6. 남은 오답과 현실적 목표

500장 오답 91장 중 미검출이 약 30장, 나머지는 오독·잡음. 직접 열어 보면 도트매트릭스 인쇄·각인·아주 작은 글씨입니다. 해상도를 올려도 안 잡히고(실험 완료), 폴백으로 일부만 살아납니다.

- **다음 큰 한 수: GPU 파인튜닝.** 실제 날짜 크롭 442장 + 도트매트릭스 합성 크롭 3,000장(`notebooks/make_synth_dotmatrix.py`)이 준비돼 있고, Colab 노트북(`notebooks/finetune_rec_colab.ipynb`)에 올려 30 epoch 돌리면 됩니다. **GPU 쓸 수 있는 분이 맡아 주세요.** 결과 모델은 `bash notebooks/after_train.sh` 로 500장에서 77.0% 와 비교합니다. 기대 +5~8%p.
- 그 외 +1~2%p 후보: 날짜 2개 이미지 규칙, 수입 DD.MM.YYYY 형식.
- **96~97% 는 이 데이터 화질로는 불가**하다고 판단합니다. 사람도 못 읽는 이미지가 남습니다. 전부 잘 되면 85~88% 가 현실적 상한이고, 그 위로 무리한 변경을 넣으면 오히려 떨어질 위험이 큽니다.

## 7. 직접 돌려 보려면

```bash
git checkout seohyun-paddleocr && git pull
pip install -r requirements.txt        # Python 3.10 권장. torch +cpu 는 extra-index 에서 받음
bash download_weights.sh               # EasyOCR 2개 + Paddle 탐지·인식 + 예비 OpenCV
ITDA_INPUT_DIR=./val_images ITDA_OUTPUT_PATH=./submission.csv jupyter nbconvert --to notebook --execute predict.ipynb --output /tmp/run.ipynb
```

환경변수: `ITDA_DOTFIX=0`(폴백 끄기), `ITDA_DET=craft`·`ITDA_REC=easyocr`(예전 구성 비교), `ITDA_DEBUG=1`(장별 OCR 텍스트 출력), `ITDA_THREADS=4`.
