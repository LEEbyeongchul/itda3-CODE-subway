## 2. 2페이지 — 설계 논리 (왜 이렇게 했나)

근거는 전부 `docs/기술_설명.md` §8, `docs/실험_기록.md` §6~7 에 있다.

1. **속도 한도가 설계를 결정했다.** 채점 = 4코어 CPU, 셀 타임아웃 2,400s, GPU 없음. CRAFT+EasyOCR 은 Colab 2vCPU 실측 14.2s/장 → 탐지기·인식기 전부 PaddleOCR mobile 로 교체해 1.9s/장. 정확도도 같이 올랐다 (39.1 → 67.7%, 133장).
2. **규칙은 오답을 보고 하나씩.** 매 규칙마다 튜닝셋(블록 6·9·10) 에서 실험 → 측정셋(블록 1~5, 튜닝에 한 번도 안 씀) 에서 **회복/퇴보를 따로 세어** 퇴보 0 인 것만 채택. 300장 ±1%p 는 잡음으로 보고 버림 (box_thresh 실험이 그 예: 300장 +1%p 였는데 500장 −12장).
3. **파인튜닝은 폴백으로만.** 393장 학습 인식기는 단독 +38/−27 로 불안정. 사전학습이 NONE 낸 장에만 쓰면 +7/−0. "둘이 서로 다른 데서 틀린다"는 관찰이 근거. 합성 도트매트릭스 3,000장 학습은 NONE 은 줄였지만 정밀도가 떨어져(84→81%) 기각.
4. **NONE 정책.** 후보 없으면 찍지 않고 NONE. 오답과 NONE 이 같은 0점이면 찍는 게 기대값상 손해가 아니지만, 정답에 NONE 이 실제로 존재하고(연도 없음 2.5%, 일 없음 3.3%) 도메인 운영에서는 "모르면 사람에게 넘긴다"가 맞다.
5. **완주 보장.** 가드는 정확도를 올리지 않는다. 채점 서버 속도를 모르는 상태에서 0점을 구조적으로 막는 장치. 발동 검증(예산 100s 강제 → 단계 상승 사슬 → CSV 100행) 완료.

## 5. 속도/오탐 최적화 전략 (2p ②)

- 640px 축소 탐지 + 필요할 때만 1024 (사다리)
- 인식은 글자 크기순 상한 30박스, 연도 포함 날짜를 찾으면 그보다 작은 글자는 생략 (조기 종료)
- 검출은 장당 1회, 2패스는 크롭 재인식만 (검출기가 CPU 비용의 대부분)
- 배치 인식 8개 (16개 498ms → 321ms)
- 폴백은 후보 없는 장(약 6~15%)에만 비용이 든다
- 오탐 억제: 신뢰 등급(완전 날짜 > 공백·6자리 > 연월 > 월일), 긴 숫자열 마스킹, 연도 범위, 답한 것의 정밀도 86%
- 시간 예산 가드 3단계

## 14. 가중치·파일이 어디에 있나 (자주 묻는 것)

| 것 | 어디에 | 비고 |
| --- | --- | --- |
| 파인튜닝 인식기 가중치 (7.2MB) | **GitHub Release** 태그 `weights-v1` 의 첨부 파일 `en_PP-OCRv5_mobile_rec_ft.zip` — https://github.com/LEEbyeongchul/itda3-CODE-subway/releases/tag/weights-v1 | 규정상 git 커밋 금지(안내서 §4: `.pt`·`.pth` 등 Release Assets 또는 외부 링크 + `download_weights.sh`). `weights-v1` = 태그(폴더 이름), zip = 그 안의 파일. 같은 것 |
| 사전학습 탐지기 `PP-OCRv5_mobile_det`, 인식기 `en_PP-OCRv5_mobile_rec` | PaddleOCR 공식 저장소 | `download_weights.sh` 가 받아 `weights/` 에 둠 |
| headless OpenCV 예비본 | PyPI 휠 | 〃 (libGL 없는 Linux 대비) |
| `predict.ipynb`, `download_weights.sh`, `requirements.txt`, `docs/`, `notebooks/`, `labels/` | git `integrate` 브랜치 | 푸시됨. 동결 뒤 main 으로 |
| 학습 데이터 zip (`rec_train.zip` 393장, `rec_train_v2.zip` 합성 포함), Colab 결과 zip (`itda_en_rec_infer*.zip`) | 병철 PC `바탕화면/코랩_파인튜닝/` | 저장소 밖 (`data/`·`weights/` 는 gitignore). 필요하면 드라이브 공유. 재생성은 `make_rec_dataset.py` 로 가능 |
| 서현 PC 의 CPU 파인튜닝 체크포인트 (`train_out/`) | 서현 PC | 채택 안 함. 요약서엔 "CPU 2 epoch 시험" 한 줄 |
| 측정 결과 CSV (500장·803장·3,352장 예측, 평가표) | `results/` (서현 브랜치 → integrate 에 포함) | 폴백 후 재측정본은 동결 때 추가 |

**새 PC 에서 전부 받는 순서** (요약서 "재현" 문단과 같음):
```bash
git clone -b integrate https://github.com/LEEbyeongchul/itda3-CODE-subway.git && cd itda3-CODE-subway
pip install -r requirements.txt          # Python 3.10
bash download_weights.sh                 # 사전학습 + Release 파인튜닝 + 예비 OpenCV, 약 1분
ITDA_INPUT_DIR=./val_images ITDA_OUTPUT_PATH=./submission.csv jupyter nbconvert --to notebook --execute predict.ipynb --output run.ipynb
```
노트북 첫 출력에 `인식기: 사전학습 1순위 + NONE 시 파인튜닝(en_PP-OCRv5_mobile_rec_ft) 폴백` 이 찍히면 가중치까지 정상.
