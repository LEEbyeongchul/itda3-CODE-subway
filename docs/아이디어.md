## 한 페이지 요약 (회의 시작할 때 이것만 읽어도 됨)

**이 아이디어가 뭔지**
물류센터(컬리·쿠팡 창고)에 우유·두부·빵이 트럭으로 들어온다. 창고는 **기한 빠른 것부터 먼저 내보내야** 하니까, 들어오는 모든 상품의 기한을 컴퓨터에 넣어야 한다. 지금은 그걸 **사람이 박스를 보고 눈으로 읽어서** 한다. 그 사람 눈을 카메라 + OCR로 바꾸자는 것.

**왜 편의점보다 나은지**
- 편의점: "알바야, 앞으로 냉장 상품 들어오면 사진도 찍어" → **새로 시키는 일**. 귀찮고, 일부 상품만 해당
- 물류센터: 검수자가 이미 **모든 상품** 기한을 읽고 있음 → 그 일을 **대신 해주는 것**. 일이 줄어듦

**조사해보니 (2026-09-08)**
1. **진짜 사람이 하나하나 읽나?** → 반쯤 맞음. 납품업체가 "이 박스 기한은 5월 29일"이라고 서류에 미리 써서 보내고, 검수자는 그 서류가 **실물이랑 맞는지 눈으로 확인**한다. 그러니까 우리 OCR은 "기한 입력"보다 **"서류랑 실물이 다른 걸 잡아주는 것"**에 가깝다. 서류 값이 있으니 OCR 결과와 비교해서 틀린 걸 더 잘 잡을 수 있다 → 논리가 오히려 단단해짐. 단, 검수자가 정확히 어떻게 하는지는 인터넷에 없어서 **현장 사람한테 물어봐야 함**
2. **이미 누가 하고 있나?** → 미국은 있음(Scandit이 마트 매대 점검용으로 판매, 폐기 40% 감소 주장). 한국 물류창고 사례는 못 찾음. "된다는 건 증명됐는데 한국 창고엔 아직 없다" 상태
3. **하면 안 되는 이유?** → 하나 큼. 식약처가 **상품 QR에 기한을 넣어 계산대에서 자동 차단(푸드QR)** 추진 중. 다 되면 OCR 필요 없어짐. 근데 지금은 강제 아닌 자율, 참여 130곳뿐, 공장 라인당 1억 원이라 다들 미루는 중. 앞으로 몇 년은 **QR 없는 상품이 대부분** → 그동안 OCR이 필요. 심사위원이 "푸드QR 있는데요?" 하면 이렇게 답하면 됨
4. **편의점 안에서 틀렸던 것** → 기한 지난 걸 팔면 영업정지라고 했는데 실제로는 **과태료 30만 원**. "가게 문 닫는 문제"는 과장이었음. 편의점 안을 버린 게 더 맞았던 셈

**정리**
> 창고 검수자가 눈으로 하던 기한 확인을 카메라가 대신한다.
> 모든 상품에 적용되고, 폐기·반품·인건비가 매일 줄어든다.
> "QR 오면 필요 없지 않나"에는 "몇 년간은 QR 없는 상품이 대부분"이라고 답한다.
> 회의 전에 물류센터에서 일해본 사람 한 명만 찾아서 물어보면 된다.

## 1. 출발점이 되는 핵심 통찰

**바코드(EAN-13)에는 소비기한이 없다.**

- 바코드는 "무슨 상품인지"만 알려준다. 기한·로트가 담기는 GS1-128은 물류 박스용이고 낱개 상품에는 거의 없다
- 그래서 소비기한은 **항상 사람이 눈으로 읽는다**
- OCR은 "바코드 스캔 + 사진 1장"으로 이 수기 단계를 없애고, 기한을 **데이터**로 만든다

### 도메인 선택 기준 (편의점 안을 버린 이유)

편의점 안의 한계: OCR이 **"안 하던 일을 추가로 시키는 것"**이라 일부 상품군에만 효과가 나고 도입 명분이 약함.
→ 기준을 바꿈: **"이미 모든 상품에 대해 사람이 매번 기한을 읽고 기록하고 있는 곳"**을 찾는다.
그러면 OCR은 새 업무가 아니라 기존 수작업의 대체가 되고, 효율은 100% 적용된다.

## 2. 메인 아이디어: 신선식품 물류센터·풀필먼트 입고 검수 자동화

### 한 줄 요약
> 물류센터는 FEFO(기한 빠른 것부터 출고)로 돌아가고, FEFO를 하려면 **입고되는 모든 식품의 기한이 WMS에 들어가야 한다.**
> 지금 그 입력·검증을 사람 눈이 한다. 이걸 OCR로 바꾸면 **입고 전 라인 100%**에 적용되고, 폐기·반품·인건비가 **매일** 줄어든다.

타겟 기업 후보: 컬리·쿠팡 프레시·SSG(이커머스 풀필먼트) / CJ프레시웨이·아워홈(B2B 식자재 유통)

### 2-1. 지금 어떻게 돌아가나 (As-Is)

1. **공급사 납품**: 발주서에 기한·제조일자를 기재하고, 박스에 상품정보를 부착해 납품 (쿠팡: 기한 관리 상품군은 발주서와 동일한 상품정보 부착 요구)
2. **입고 검수**: 검수자가 실물 박스·낱개의 기한을 **눈으로 읽어** ① 발주서 값과 맞는지 대조하고 ② 잔여기한 기준(컬리: 입고일 기준 잔여 소비기한 50~70% 이상, 이마트: 기한 1년 상품은 6개월 이상)을 충족하는지 판단
3. **전산 등록**: 기한별로 LPN(입고 단위) 라벨을 발행해 재고를 기한 단위로 분리 (쿠팡: 제품 바코드 + LPN 바코드(제조일자/유통기한/포장일자) 기준으로 분류)
4. **보관·출고**: WMS가 등록된 기한으로 FEFO 출고. 출고 허용 잔여기한 미달 재고는 폐기 (이마트: 기한 80% 경과 시 판매 종료·폐기)

> ⚠️ 주의: "검수자가 기한을 하나하나 타이핑한다"는 **1차 문서는 확보 못 함**. 확인된 것은 (a) 발주서/ASN에 공급사가 사전 기재, (b) 센터에서 기한별 LPN 라벨을 발행, (c) 잔여기한 기준을 검수 단계에서 판정한다는 것.
> 즉 현장은 "완전 수기 입력"보다 **"공급사 신고값 + 사람 눈 대조·판정"** 구조일 가능성이 높다. → OCR의 역할을 "입력"이 아니라 **"실물 검증 자동화"**로 잡는 게 정확하다. (§4-1 참고, 현직자 인터뷰 필요)

### 2-2. 어디에 문제가 있나

**문제 1. 신고값과 실물이 다를 때 잡아내는 건 사람 눈뿐이다**
- 공급사가 발주서에 쓴 기한과 실제 납품된 로트의 기한이 다르면(오래된 로트 혼입, 오기재) 검수자가 육안으로 걸러야 함
- 못 거르면 WMS에 틀린 기한이 들어가고 → FEFO가 깨짐 → 오래된 재고가 안 나가고 창고 안에서 기한 경과 → **전량 폐기**(입고가 그대로 손실)

**문제 2. 잔여기한 판정이 암산이다**
- "이 상품 기한 1년, 오늘 기준 몇 % 남았나"를 라인마다 사람이 계산. 바쁘면 대충 통과
- 기준 미달이 들어오면 창고에서 팔 수 있는 기간이 짧아져 폐기율 상승, 또는 고객에게 임박 상품이 나가 클레임

**문제 3. 검수가 병목이다**
- 하루 수천~수만 라인 × 라인당 기한 읽고 대조·판정 몇 초 = 검수 인건비 + 도크 대기 시간
- 냉장 상품이 도크에서 기다리면 콜드체인 품질 저하

**문제 4. 표기가 제각각이라 읽는 것 자체가 느리고 틀린다**
- `2026.05.29` / `26.05.29` / `20260529` / 제조일자+보관기간 / 농산물 `A01`(알파벳=월) 코드 등
- 2023년 소비기한 표시제 전환 후 유통기한·소비기한 혼재 (냉장 우유류는 2031년까지 유통기한 유예)

**문제 5. 기록이 안 남는다**
- 검수자가 눈으로 보고 넘긴 건 "봤다"는 기록만 남고, 실물 기한 이미지·값은 안 남음 → 사후 폐기 원인 분석(공급사 탓 vs 수요예측 탓) 불가

### 2-3. 그래서 어떻게 해야 하나 (To-Be)

| 단계 | 지금 | OCR 도입 후 |
| --- | --- | --- |
| **검수** | 눈으로 읽고 발주서와 대조 | PDA 카메라로 촬영 → 기한 자동 추출 → **발주서 값과 자동 대조**, 불일치 시 즉시 알림 |
| **잔여기한 판정** | 암산 | 기준 미달이면 **입고 시점에 자동 반려** |
| **전산 등록** | 신고값 기준 LPN 발행 | 실물 검증된 값으로 LPN 발행 → FEFO 정확도 향상 |
| **미인식(NONE)** | — | 사람이 그 라인만 직접 확인 (전수 육안 → 예외만 육안) |
| **기록** | 없음 | 실물 기한 값 + 이미지 로그 → 공급사별 납품 신선도 KPI, 폐기 귀책 분리 |

**왜 전체 적용인가**: 물류센터에 들어오는 **모든 식품 라인**이 대상. 예외가 없다.
**왜 도입 저항이 낮은가**: 검수자 업무가 늘지 않고 줄어든다(읽고 대조 → 찍고 확인).

### 2-4. ROI 항목 (숫자는 확보 필요)

| 항목 | 계산 방식 | 근거 자료 |
| --- | --- | --- |
| 창고 내 기한 경과 폐기 감소 | 폐기율 × 취급액 × OCR로 줄일 수 있는 비율 | 컬리 폐기율 <1%, 대형마트 3%, 슈퍼 7~8% (2022 보도) |
| 잔여기한 미달 출고 클레임 감소 | 클레임 건당 (환불+재배송+반품 물류비) × 건수 | 확보 필요 |

### 2-5. 모델 설계와의 연결 (심사 논리성 포인트)

- 오탐(틀린 날짜를 자신 있게 출력) = 틀린 기한이 WMS에 들어감 = FEFO 붕괴 = **가장 비싼 오류**
- 미인식(NONE) = 그 라인만 사람이 확인 = 싸고 안전한 오류
- → **"확신 없으면 NONE"** 원칙이 비즈니스적으로 정당 → 신뢰도 임계값 설계 근거
- 발주서 신고값이 있으므로 **OCR 결과 vs 신고값 교차검증**이 가능 → 단독 OCR보다 오탐을 더 줄일 수 있다는 아키텍처 논리
- 정규화(`year/month/day/final_date`)가 곧 WMS 입력 스키마 → 대회 출력이 그대로 서비스 데이터

### 2-6. 운영 구조 (초안)

- 검수용 PDA/스마트폰에서 **온디바이스 CPU 추론** → 채점 환경(4-core CPU, GPU 없음)과 서사 일치. 해외 상용 솔루션(Scandit)도 온디바이스 방식
- WMS로는 이미지가 아닌 **추출값 + 신뢰도 + 신고값 일치 여부**만 전송 → 서버 비용 극소화
- 확장: 하류(급식 검수, §3-A)와 상류(제조사 출하)에 같은 모델 재사용

| D | 편의점 냉장 매대 (기존 안) | 제조사 납품 단기 상품은 POS 관리 없음 | 입고 스캔 → POS 차단 | **보류 사유**: ① 자유업 편의점 처분은 **과태료 30만 원**(영업정지 아님) → 리스크 ROI 약함 ② 식약처 **푸드QR**이 정확히 이 문제(QR 소비기한 → POS 차단)를 풀려는 중 |

## 4. 팩트체크 결과 (2026-09-08 웹 조사)

### 4-1. "입고 검수를 사람이 하나하나 하는 게 맞나?"

**부분 확인.**
- 확인됨: 쿠팡 IB 공정은 제품 바코드 + LPN 바코드(제조일자/유통기한/포장일자)로 분류·적재. 농산물은 `A01` 같은 코드로 포장일자 표기. 컬리는 잔여 소비기한 기준(입고일 기준 50~70%)으로 입고 판정. 학교급식은 검수일지에 유통기한 기록 의무
- 확인 못 함: 검수자가 기한을 직접 타이핑하는지, 공급사 신고값을 대조만 하는지. 국내 물류 입고 단계에 유통기한 OCR을 상용 도입한 사례도 검색에서 발견 못 함 (국내 검색 결과는 소비자용 냉장고 앱 수준)
- 해외: Scandit(Albertsons 등)·Zebra가 매장 선반 점검·마크다운용 유통기한 OCR을 상용화. 폐기 최대 40% 감소, 캡처 시간 60% 단축 주장. **물류 입고 단계 사례는 별도 확인 필요**

### 4-2. "도입하면 안 되는 / 안 한 이유가 있나?" — 심사 Q&A 예상 반론과 답

| 반론 | 사실 | 우리 답 |
| --- | --- | --- |
| **① 푸드QR·2D 바코드가 오면 OCR 필요 없어지지 않나?** | 식약처가 소비기한 탑재 푸드QR + POS 자동 차단을 추진 중. 2026 상반기부터 샌드위치·김밥 등 단기 상품 출시, 롯데웰푸드 4개 공장 적용, SPC삼립 검토. 도입 시 행정처분 경감(편의점 과태료 30만 → 경고). GS1 Sunrise 2027로 리테일 POS는 2D 판독 준비 | **자율 참여**(의무 아님), 규제특례 기반이라 **법적 근거 없음**(최대 4년), 2025년 기준 **130업소 483품목**, 제조사 라인당 약 1억 원 설비·생산효율 저하 우려, 유통사 POS 교체 부담. → 수년간 QR 없는 상품(중소 제조사·수입·농축수산물)이 대다수. OCR은 **전환기 브릿지 + QR 미부착 상품 커버**. 또한 Sunrise 2027은 "POS가 읽을 수 있어야" 하는 목표이지 제조사 인쇄 의무가 아님 |
| **② OCR 정확도가 식품 안전에 쓸 만한가?** | 도트매트릭스·잉크젯 인쇄, 곡면·투명 포장에서 범용 OCR 정확도 낮음 (도트매트릭스에서 Tesseract 55%, Google API 60% 보고) | 이게 **지금까지 사람이 해온 기술적 이유**. 우리 설계 포인트: 날짜 특화 후처리 + 신뢰도 임계값 + NONE 처리 + 발주서 신고값 교차검증으로 오탐을 구조적으로 억제 |
| **③ 물류는 박스 단위인데 낱개 촬영은 병목 아닌가?** | 입고는 박스·팔레트 단위. 박스 겉면에 기한 인쇄 또는 상품정보 라벨 부착 | 촬영 단위를 **박스 라벨/겉면**으로 설정. 낱개는 샘플링 검증. 처리량 논리로 "라인당 몇 초"를 제시 |
| **④ 기존 WMS 연동·단말 비용** | 일반적 도입 장벽 | 온디바이스 추론이라 서버 증설 없음, 기존 PDA 카메라 활용, WMS에는 텍스트 API만 |

### 4-3. 편의점 안 관련 교정
- 편의점(100평 미만 자유업)의 소비기한 경과 판매 처분은 **과태료 30만 원**. 영업정지는 식품접객업·제조업(15일), 100평 이상 식품판매업(7일). → 이전에 세운 "영업정지 기대손실" 논리는 편의점에 **적용 안 됨**
- 100평 미만 편의점은 구청 위생점검 대상에서도 빠져 있음 → 규제 압력 자체가 약함

### 4-4. 확보한 숫자
- 컬리 신선식품 폐기율 7년간 1% 미만 / 대형마트 약 3% / 슈퍼 7~8% (2022.3 보도, 통계청 인용)
- 가공식품 유통 중 반품 폐기 손실 연 6,464억 원, 축산가공품 1,603억·음료 1,011억 (식품저널, 연도 확인 필요)
- 이마트 입점 기준: 기한 1년 상품은 6개월 이상 잔여, 80% 경과 시 판매 종료·폐기
- Scandit: 폐기 최대 40% 감소, 아이템별 캡처 시간 60% 단축 (자사 주장)
- 푸드QR: 2025년 국내 가공식품 130업소 483품목, 2026년 수입식품·농축수산물 확대
