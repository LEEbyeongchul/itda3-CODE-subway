# 기술적 계획 — 소비기한 OCR 파이프라인 고도화

> 제출 마감 2026-09-15(화) 23:59. 채점 환경: GPU 없는 4코어 CPU, 인터넷 차단, 40분 제한, Python 3.10.

---

## 0. 한 줄 목표

**이미지 전체를 OCR에 넣지 말고, 소비기한 영역 → 날짜 블록 → 연·월·일 토큰까지 잘라낸 뒤 토큰만 OCR하고 규칙으로 조합한다.**

전체 이미지 OCR은 영양성분표, 바코드, 품목보고번호가 전부 후보로 올라와 오탐이 많다. 토큰 단위로 자르면 OCR은 "이 2자리 숫자가 뭔가"만 답하면 되므로 작은 모델로도 정확도가 나온다. 무거운 범용 OCR보다 **경량 모델을 우리 도메인 데이터로 학습**하는 쪽이 CPU 채점에 유리하다.

## 1. 목표 파이프라인

```
원본 이미지
  │
  ├─ ⓪ EXIF 회전 보정                 (지금도 하고 있음. 유지)
  │
  ├─ ① Full Detection   YOLOv11n      상품 이미지 전체에서 "소비기한이 포함된 영역"을 한 덩어리로 탐지
  │                                    → 영양성분표·바코드·품목보고번호가 후보로 올라오는 것을 원천 차단
  │
  ├─ ② Date Detection   YOLOv11n      Full 영역 안에서만 날짜 블록 재탐지. 클래스: date / due / code
  │                                    → 좁은 영역을 집중 탐지해 정확도 상승
  │
  ├─ ③ Token Detection  YOLOv11n      Date 블록 안에서 연·월·일 토큰을 각각 박스로 분리
  │                                    클래스: Y4(4자리 연도) / ENG_MON(영문 월) / NUM2(2자리 숫자)
  │
  ├─ ④ Recognition      PaddleOCR v3   토큰 하나씩 잘라 문자 인식. 숫자·영문 전용 인식기, 약 9MB
  │                     (인식기만)     토큰은 2~4글자라 인식이 쉬움
  │
  ├─ ⑤ 후처리 규칙                     토큰 위치 순서 + 값 규칙으로 날짜 조합 (4절)
  │
  └─ ⑥ 출력              YYYY-MM-DD / NONE-MM-DD / YYYY-MM-NONE / NONE
```

**단계적으로 간다.** ①~③을 한 번에 다 만들지 않는다. 먼저 ④ 인식기만 교체해 효과를 보고, 그 다음 ① Full 탐지 하나만 넣고, 시간이 남으면 ②③을 붙인다. 각 단계마다 정확도와 CPU 시간을 재서 다음 단계로 갈지 결정한다.

## 2. 데이터

### 2.1 지금 있는 것

| 항목 | 수량 | 상태 |
| --- | --- | --- |
| 대회 배포 이미지 | 3,352장 | `images/` |
| 날짜 텍스트 라벨 (final_date + 원문 형식 + 태그) | 3,352장 | 1·2차 1,000장 진행 중, 3차 2,352장 예정 |
| 박스 라벨 (Full / Date / Token 위치) | 0장 | **없음. 탐지 모델을 쓰려면 새로 만들어야 함** |

### 2.2 박스 라벨 만들기 (탐지 단계를 도입할 경우)

3,352장을 전부 손으로 박스 라벨링할 시간은 없으니 **반자동**으로 간다.

1. 현재 EasyOCR 파이프라인이 정답을 맞힌 이미지(예상 60~70%)에서 EasyOCR이 준 텍스트 박스 좌표를 그대로 **자동 박스 라벨**로 쓴다. 정답 문자열과 일치하는 박스만 채택.
2. 자동 라벨 실패분 중 300~500장만 손으로 박스를 친다. 라벨링 도구는 LabelImg 또는 Roboflow.
3. 토큰 박스는 날짜 박스 안에서 구분자(`.` `/` `-` 공백) 기준으로 자동 분할하고, 라벨은 값으로 정한다. `2026` → Y4, `FEB` → ENG_MON, `06` → NUM2.

**라벨 체계**

| 단계 | 클래스 | 이유 |
| --- | --- | --- |
| Full | full | 소비기한 문자열이 들어 있는 전체 영역. 외부 문자열 혼동 방지 |
| Date | date, due, code | 국내 상품은 제조일자 표기가 드물어 "제조" 클래스를 따로 두면 주변 숫자열과 혼동됨 → 날짜가 아닌 숫자열은 전부 code로 |
| Token | Y4, ENG_MON, NUM2 | **위치가 아니라 값의 의미로 라벨링.** 포맷이 YY-MM-DD든 DD-MM-YY든 토큰 라벨은 같다. 어느 NUM2가 월이고 일인지는 후처리에서 위치로 결정. 라벨 노이즈가 줄고 포맷이 바뀌어도 학습 데이터가 그대로 쓰인다 |

### 2.3 OCR 학습용 토큰 크롭

토큰 박스가 생기면 잘라서 텍스트 라벨과 짝지은 이미지를 만든다. 3,352장 × 평균 3토큰 = 약 10,000장 확보 가능.

### 2.4 데이터 보강 (Phase 4, 시간 남으면)

편의점 소비기한 OCR에서 흔히 나오는 오류 유형. 우리 라벨의 태그(`b` 흐림, `t` 작음, `e` 각인, `d` 일먼저)와 format 열로 같은 유형을 바로 뽑을 수 있다.

| 오류 유형 | 대응 |
| --- | --- |
| ① YYYYMMDD 구분자 없음 탐지 실패 | 라벨 format 열에서 `YYYYMMDD` 건수 확인 후 합성 데이터로 보강 |
| ② MM/DD 탐지 실패 | `MM.DD` 형식 건수 확인 |
| ③ 구분자 없는 DMY | `d` 태그 건수 확인 |
| ④ Blur | `b` 태그 이미지를 hard sample로 |
| ⑤ 7 → 1 오인식 | 오답 집계에서 확인, 해당 숫자 조합 보강 |
| ⑥ 0+숫자 (03, 05, 09) 인식률 낮음 | 오답 집계에서 확인, 해당 숫자 조합 보강 |
| ⑦ 영문 월 일부 실패 | `MON DD YYYY` 형식 건수 확인, 영문 월 데이터 보강 + 대소문자 정규화 |

합성 데이터 생성 방법
- 이미지 편집 모델(Inpainting)로 기존 사진의 날짜 부분만 원하는 문자열로 바꿔 넣으면, 실사에서 드문 포맷(YYYYMMDD, MM.DD, Dot-matrix)을 원하는 만큼 만들 수 있다.
- **규정 확인이 먼저다.** 유료 VLM API는 추론 시 실시간 호출이 금지인데, 학습 데이터 생성용 오프라인 사용이 허용인지 운영진에게 물어본다. 허용이면 비용을 보고서에 명시한다.
- 불허이거나 시간이 없으면 대안: Pillow로 Dot-matrix 폰트 날짜를 실제 포장 사진 위에 합성. 품질은 떨어지지만 비용 0.

## 3. 모델

### 3.1 탐지: YOLOv11n

- 세 단계 모두 YOLOv11 nano. 약 6MB. CPU에서 640px 입력 기준 장당 50~100ms 예상. **실측 필수.**
- 학습은 Colab GPU. 추론은 `ultralytics` CPU. 가중치는 `weights/`에 두고 `download_weights.sh`로 받게 한다.
- 학습 순서: 사전학습 COCO 가중치 → 우리 박스 라벨로 파인튜닝.

### 3.2 인식: PaddleOCR v3 인식기 (PP-OCRv3 rec, en)

- 탐지기(DB)는 쓰지 않고 **인식기만** 쓴다. 입력은 YOLO가 잘라준 토큰 크롭.
- 사전학습 `en_PP-OCRv3_rec` 가중치로 시작. 허용 목록(EasyOCR, PaddleOCR, YOLOv8 등)에 있음.
- 파인튜닝은 2.3의 토큰 크롭 약 10,000장으로. 문자 사전은 `0-9`, `A-Z`, 구분자 정도로 좁힌다.
- TrOCR 같은 Transformer 인코더·디코더 OCR은 쓰지 않는다. 용량 200MB 이상에 Self-Attention 연산량이 커서 CPU에서 OCR 단계가 병목이 된다. 짧은 토큰 인식에는 9MB짜리 CTC 기반 인식기로 충분하다.

### 3.3 파인튜닝 방식

| 기법 | 내용 |
| --- | --- |
| 정규화 규칙 | 영문 월 대·소문자 비구분. FEB = Feb = feb 모두 정답. 학습 라벨도 대문자로 통일 |
| **2차 파인튜닝 (hard sample)** | 1차 학습 모델로 전체 추론 → "인식 실패 이미지"만 모아 다시 학습. 실패 = 틀린 것 + 맞혔지만 신뢰도 낮은 것 + 특정 오류 패턴(7→1, 03/05/09) |
| 과적합 방지 | 2차는 epoch을 적게. 1차의 1/3 이하로 시작해 검증셋으로 조정 |
| 검증 분리 | **1차 라벨 500장은 절대 학습에 쓰지 않는다.** 2차 500장은 튜닝용, 3차 2,352장은 학습용. "안 본 데이터에서 X%"를 말하려면 이 분리가 필요 |

## 4. 후처리 규칙

우리 데이터셋은 2019~2028년이 섞여 있고 과거 날짜도 정답이다. 따라서 "오늘 이후 날짜만 유효" 같은 실사용 앱 기준의 필터는 쓰지 않는다.

### 4.1 토큰 3개

| 패턴 | 해석 | 비고 |
| --- | --- | --- |
| Y4 NUM2 NUM2 | YYYY-MM-DD | 가장 흔함 |
| NUM2 NUM2 Y4 | DD-MM-YYYY | 연도가 뒤면 일이 먼저 |
| Y4 ENG_MON NUM2 | YYYY-MM-DD | |
| NUM2 ENG_MON Y4 | DD-MM-YYYY | |
| ENG_MON NUM2 Y4 | MM-DD-YYYY | 월이 맨 앞에 오는 유일한 패턴 (`FEB/21/26`) |
| **NUM2 NUM2 NUM2** | 양방향 해석 | 아래 4.3 |

### 4.2 토큰 2개

| 패턴 | 해석 | 우리 출력 |
| --- | --- | --- |
| NUM2 NUM2 | MM-DD (연도 없음) | `NONE-MM-DD` |
| ENG_MON NUM2 | MM-DD | `NONE-MM-DD` |
| Y4 NUM2 | YYYY-MM (일 없음) | `YYYY-MM-NONE` |
| NUM2 Y4 | MM-YYYY (유럽식 `12.2020`) | `YYYY-MM-NONE` |
| Y4 ENG_MON | YYYY-MM | `YYYY-MM-NONE` |

### 4.3 NUM2 NUM2 NUM2 (2자리 연도, 가장 애매)

예: `20-12-26`. 가운데가 1~12면 두 해석을 동시에 만든다.
- A) YY-MM-DD → 2020-12-26
- B) DD-MM-YY → 2026-12-20

결정 규칙:
1. 첫 토큰이 13~31이면 A는 불가능 → B 확정. (예: `30 12 23` → 2023-12-30)
2. 셋째 토큰이 13~31이면 B는 불가능 → A 확정. (예: `26.06.25` → 2026-06-25)
3. 둘 다 가능하면 **A(YY-MM-DD) 우선.** 국내 상품 대부분이 이 순서. 라벨의 `d` 태그 비율을 보고 이 기본값을 확정한다.
4. 키워드 힌트가 있으면 우선 적용: 포장에 `DD/MM/YY`, `BBD`, `BEST BEFORE` 문구가 잡히면 B.

### 4.4 날짜가 여러 개 (제조일자 + 소비기한)

- 운영진 확정 규칙: **가장 늦은 날짜**를 소비기한으로. 이미 현재 파이프라인에 있음.

### 4.5 검증

- 연도 범위 2015~2035 밖이면 다른 해석으로 재시도, 없으면 폐기.
- 월 1~12, 일 1~31 밖이면 폐기.
- 9자리 이상 숫자열(품목보고번호, 바코드)은 탐지 전에 마스킹. 지금도 하고 있음, 유지.

## 6. 일정과 단계

| Phase | 내용 | 완료 기준 | 언제 |
| --- | --- | --- | --- |
| **0. 기준선** | 1차 라벨 500장으로 현재 파이프라인 정확도·속도 측정, 오류 유형 집계 | 숫자가 나온다 | 9/9 오후 ~ 9/10 |
| **1. 인식기 교체** | 2패스 인식기를 EasyOCR → PaddleOCR v3 rec으로. 탐지는 아직 EasyOCR CRAFT 유지 | 정확도·시간 비교표 | 9/10 ~ 9/11 |
| **2. Full 탐지 도입** | YOLOv11n으로 Full 영역만 탐지 → 그 영역만 OCR. 반자동 박스 라벨 | Phase 1 대비 오탐 감소 확인 | 9/11 ~ 9/12 |
| **3. 인식기 파인튜닝** | 토큰 크롭으로 PP-OCRv3 rec 파인튜닝 + hard sample 2차 | 2차 라벨셋에서 개선 | 9/12 ~ 9/13 |
| **4. 토큰 탐지·보강** | Date/Token 탐지 추가, 합성 데이터. **시간 남을 때만** | | 9/13 ~ 9/14 |
| **5. 제출 준비** | 오프라인 재현 테스트, `download_weights.sh`, README, 커밋 해시 | Run All 2,400초 이내 통과 | 9/14 ~ 9/15 |

**Phase 1이 가장 싸고 빠른 실험이다.** 여기서 효과가 없으면 탐지 도입(Phase 2)의 우선순위를 다시 본다. Phase 4는 마감 기준으로 판단하고, 안 되면 보고서에 "향후 계획"으로 적는다.

## 8. 실험으로 정해야 하는 것

- YOLO 학습 설정: epoch, 입력 해상도(640 기본), 증강. 세 단계를 단일 모델로 할지 별도로 할지 → 별도 모델, Full부터
- PaddleOCR 파인튜닝 설정: 학습률, epoch, 배치, 2차 파인튜닝 epoch 수 → Phase 3에서 실험
- CPU 추론 시간 → 단계별로 직접 측정
- 후처리의 2자리 연도 기본 방향(YY-MM-DD vs DD-MM-YY) → 라벨 `d` 태그 비율로 결정
