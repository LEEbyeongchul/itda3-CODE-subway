# 제3회 ITDA 연합학술제 참가자 안내서

> 참가부터 본선 발표까지 필요한 규칙·일정·기술 가이드·제출 규정 정리본입니다.
> 원본 공지를 옮긴 것이며, 운영진 공지와 충돌할 경우 **공식 공지가 우선**합니다.

## 1. 개요

### 대회 목적
- 상품 뒷면 이미지에서 소비기한을 가장 정확하고 효율적으로 추출하는 **OCR 아키텍처를 설계**하고, 이를 실제 산업 도메인에 어떻게 적용할지 기획하는 대회
- 단순히 AI 모델을 실행하는 것을 넘어, "왜 이 아키텍처가 필요한가?"에 대한 논리적 이유를 설계하고 입증하는 것이 목표

### 예선 진행방식
- **라벨링 데이터 없이** 실제 상품 뒷면 사진 3,352장이 제공됨
- 사진 속 숫자 중 **정확한 소비기한 날짜만** 추출

### 본선 진행방식
- 예선에서 개발한 OCR 기술을 실제 산업 현장에 어떻게 적용·운영할지 종합 기획
- 시스템 운영 아키텍처 설계 → 비즈니스 손실 절감 ROI 기획까지 입증

### 기획 배경
- 정확도 소수점만 올리다 "이 모델이 실제 산업에서 왜 필요한가?"라는 목적성을 잃는 문제의식에서 출발
- **정확도 + 처리 속도 + 서버/운영 비용 + 도메인 활용성**을 종합 고려하는 엔지니어링 사고를 요구

## 2. 대회 소개

- **주제**: OCR 기반 상품 소비기한 정보 추출 아키텍처 설계 및 도메인 활용 기획
- **주최**: 수도권 데이터사이언스 연합학회 ITDA
  - 인하대 IBAS · 경희대 CODE · 서강대 INSIGHT · 한국외대 DAT · 성균관대 DScover

### 과제
소비기한·제조일자·바코드·영양성분·전화번호 등이 얽혀 있는 상품 뒷면 이미지를
`submission.csv` (`image_id`, `year`, `month`, `day`, `final_date`) 형태의 정규화된 날짜 표로 변환 (미인식 시 `NONE`)

### 평가 관점
| 항목 | 내용 |
| --- | --- |
| 논리성 | 모델링 및 기술 선택의 근거를 논리적으로 설명할 수 있는가? |
| 적극성 | 라벨링 규칙을 직접 정의하고, 필요시 데이터를 직접 수집·확장했는가? |
| 정확성 | 제한된 CPU 환경에서 빠른 속도와 높은 날짜 추출 정확도를 달성했는가? |
| 주체성 | 기술의 활용처와 운영 방식을 주도적으로 정의하고 기획했는가? |

## 3. 참가 유의사항

### 팀 구성 및 등록
- **참가 자격**: ITDA 소속 5개 연합학회원 (경희대·서강대·성균관대·인하대·한국외대)
- **인원**: 팀당 1인 ~ 최대 5인
- **팀명 규칙**: `[학회명]_팀명` (예: `[CODE]_소비기한잡으러왔다`)

### 개발 및 채점 환경
- **개발 환경**: Colab, 개인 PC GPU, 외부 클라우드 등 GPU 활용 자유
  - 유료 GPU/클라우드 자원을 사용한 경우 **사용 분량 및 비용을 보고서에 반드시 명시**
- **운영진 채점 환경**: Standard 4-Core vCPU (**GPU 없음**)
- **Python 버전**: Python 3.10 기준
- **의존성 고정**: `requirements.txt`에 명시된 라이브러리만 자동 설치하여 채점

### CPU 채점 환경 핵심 유의사항
학습은 Colab GPU로 하더라도 채점 서버는 **CPU 전용**입니다.
무거운 딥러닝 모델만 사용하면 CPU 추론 시 속도 감점 또는 타임아웃이 발생합니다.
개발 단계에서 반드시 `USE_GPU = False` 로 CPU 추론 속도를 사전 검증하세요.

### 외부 도구 및 API 사용 범위
- **허용**: 오픈소스 사전학습 모델 Weight (EasyOCR, PaddleOCR, YOLOv8, LayoutLM 등)
- **불허**:
  - 유료 LLM/VLM External API (실시간 API 호출)
  - 추론 시점의 사람 개입 (Human-in-the-loop)

### 부정행위 기준 (적발 시 즉시 자격 박탈)
- 외부 유료 API를 통한 추론 자동화
- 타 팀 코드 도용 및 제출 결과지 조작

## 5. 제출 파일

베이스라인 코드는 제공되지 않습니다. 추론 파이프라인과 `predict.ipynb`를 직접 구축해야 합니다.

```
itda3-{학회영문}-{영문팀명}/
├── predict.ipynb              # 메인 추론 노트북 (운영진 채점용, 필수)
├── requirements.txt           # 실행 환경 패키지 목록 (필수)
├── README.md                  # 가중치 다운로드 및 실행 가이드 (필수)
├── download_weights.sh        # [선택] 외부 가중치 다운로드 스크립트
├── notebooks/                 # [선택] 실험·분석 노트북 (채점 대상 아님)
└── weights/                   # [선택] 모델 가중치 저장 폴더
```

### predict.ipynb 작성 규칙

채점 대상 파일은 **`predict.ipynb` 단 하나**입니다. 실험용 노트북은 `notebooks/`에 자유롭게 두되 채점하지 않습니다.

**1) 첫 번째 코드셀은 반드시 아래 형태의 설정 셀**

```python
# ===== CONFIG =====
import os
INPUT_DIR   = os.environ.get("ITDA_INPUT_DIR",  "./val_images")
OUTPUT_PATH = os.environ.get("ITDA_OUTPUT_PATH", "./submission.csv")
# ==================
```

운영진은 환경변수 `ITDA_INPUT_DIR` / `ITDA_OUTPUT_PATH`만 주입한 뒤 노트북을 순차 실행합니다.
`os.environ.get` 형태를 그대로 사용하세요. **값을 직접 대입하면 주입이 무시되어 채점 불가**입니다.

**2) 실행 방식: 위에서 아래로 전 셀 순차 실행(Run All)**
- 셀 순서가 곧 실행 순서. 위 셀이 아래 셀 결과에 의존하지 않도록 작성
- `input()`, `getpass()` 등 사용자 입력 대기 코드 금지 → 입력 대기 시 타임아웃 처리
- 노트북 출력(output) 저장 여부는 채점에 영향 없음

**3) 최종 셀은 `OUTPUT_PATH`에 submission.csv 저장**
- 인덱스 반드시 제외: `df.to_csv(OUTPUT_PATH, index=False)`
- 인덱스가 포함되면 컬럼 구조가 밀려 **자동 채점기 파싱 에러(0점)** 발생
- 실행 후 해당 경로에 파일이 없거나 비어 있으면 **정량 60점이 0점 처리**

**4) 제출 전 자가 검증**

```bash
ITDA_INPUT_DIR=/tmp/test_imgs ITDA_OUTPUT_PATH=/tmp/out.csv jupyter nbconvert --to notebook --execute predict.ipynb --output /tmp/executed.ipynb
```

에러 없이 완료되고 `/tmp/out.csv`가 생성되어야 합니다.

## 10. Q&A 및 문의

### FAQ

**Q. 제공된 3,352장 Unlabeled 데이터를 전부 수동 라벨링해야 하나요?**
A. 아닙니다. 정규식/OCR 기반 룰로 자동 라벨을 생성하거나, 예외 케이스 일부만 수동 라벨링해 학습시키는 등 주체적인 전략을 활용하면 됩니다.

**Q. 본선 도메인 기획은 어떤 것을 의미하나요?**
A. 설계한 OCR 아키텍처를 '편의점 유통기한 관리', '식품 기부 푸드뱅크', '물류창고 입출고 자동화' 등 특정 기업/산업에 실제 도입한다고 가정하고, 서버/온디바이스 운영 구조 및 예상 비용을 산출하는 기획입니다.

**Q. 본선 발표 운영 및 시간 배분은?**
