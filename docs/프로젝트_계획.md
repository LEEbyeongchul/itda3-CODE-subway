## 2. 우리가 만드는 것

```
입력: 사진 폴더 (500장, 운영진이 비공개로 준비)
        ↓  predict.ipynb 를 위에서 아래로 실행
출력: submission.csv
      image_id, year, month, day, final_date
      000001,   2027, 06,    26,  2027-06-26
      000002,   NONE, 10,    14,  NONE-10-14     ← 연도가 없는 제품
      000003,   NONE, NONE,  NONE, NONE          ← 날짜가 없는 제품
```

채점은 **연·월·일 각각** 맞으면 점수를 줍니다(부분점수). `NONE`도 정답이 될 수 있습니다.

## 3. 점수는 어디서 나오나

| 항목 | 배점 | 우리가 할 일 |
| --- | --- | --- |
| 날짜 추출 정확도 | **50** | 파이프라인 정확도 올리기 |
| CPU 추론 속도 | 10 | 500장을 40분 안에, 가능하면 훨씬 빠르게 |
| 아키텍처 구조도 (요약서 1쪽) | 15 | 파이프라인 그림 + 설명 |
| 설계 논리·최적화·활용 (요약서 2쪽) | **25** | "왜 이 구조인가"를 실측 숫자로 설명 |
| 직접 라벨링 가산점 | +5 | 검증셋 250장 라벨링 (어차피 필요한 일) |

**정성 40점 + 가산점 5점 = 45점이 문서에서 나옵니다.** 정확도만 파면 절반을 버리는 셈이라, 실험할 때마다 "숫자를 남기는" 습관이 중요합니다.

## 5. 파이프라인 구조 (B 플랜: 2-Pass Hybrid)

### 쉽게 말하면

사진에서 글자를 찾는 일(검출)과 읽는 일(인식)은 둘 다 느립니다. 그래서 **찾을 때는 작은 사진으로 대충 찾고, 읽을 때는 날짜로 보이는 부분만 원본에서 자세히 읽습니다.**

### 한 장이 지나가는 길

```
① 사진 열기 + 회전 바로잡기        사진의 8.7%가 옆으로 누워 있음 (EXIF)
② 작게 줄여서 글자 위치 찾기        640px, 장당 1번만 (여기가 제일 비쌈)
③ 큰 글자부터 읽기                  날짜 스탬프는 잔글씨보다 큼 → 찾으면 잔글씨는 건너뜀
④ 날짜 골라내기                     품목보고번호·바코드 같은 긴 숫자 제거 → 날짜 형식 검사
   └ 아무것도 못 찾으면 ②를 1024px로 한 번 더
⑤ 후보 부분만 원본에서 다시 읽기    흐리게 읽힌 숫자 교정
⑥ 여러 개면 가장 늦은 날짜 선택     운영진 확정: 제조일자·소비기한 병기 시 나중 것
```

### 왜 이 구조인가 (요약서 2쪽에 들어갈 핵심)

- 검출 시간은 픽셀 수에 비례: 640px 2.2초 vs 1280px 12초. 날짜 스탬프는 커서 640에서도 잡힘
- 인식 시간은 박스 수에 비례: 박스당 0.17초, 영양성분표가 있으면 50개 → 8.5초. 큰 글자부터 읽고 멈추면 대부분 생략
- 가장 위험한 오탐은 **품목보고번호** (`20130628…`이 날짜처럼 보임) → 9자리 이상 숫자열은 통째로 삭제

### 지금 상태

- 처음부터 끝까지 실행됨, CSV 나옴, 오프라인 로드 확인
- 어려운 케이스 11장 테스트: 정답 아는 10장 중 **완전일치 5 · 부분 1 · 미인식 4**
- 속도: 개발 PC에서 장당 5~7초 (예산 4.8초 — 채점 서버 속도 미확인)
