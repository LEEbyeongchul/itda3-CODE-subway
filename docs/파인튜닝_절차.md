> 계획서 Phase 3. 목표: 우리 포장 사진의 날짜 크롭으로 `en_PP-OCRv5_mobile_rec` 를 파인튜닝해 미검출·오독을 줄인다.
> 확인 근거: PaddleOCR 공식 문서 text_recognition 모듈 (2026-09-10 조회), 저장소 `configs/rec/PP-OCRv5/multi_language/en_PP-OCRv5_mobile_rec.yaml`.

## 0. 데이터 만들기 (로컬, 이 저장소)

```bash
python notebooks/make_rec_dataset.py --blocks 6,7,9,10,14 --val-blocks 6 --out data/rec_train
```

- 출력: `data/rec_train/imgs/*.jpg`, `train_list.txt`, `val_list.txt`, `manifest.csv`, `sheet_XX.jpg`
- **블록 1~5 는 절대 넣지 않는다** (측정 전용. 스크립트가 거부한다).
- `sheet_01.jpg` 부터 열어 빨간 플래그(`multiline?`, `extra_text`, `truncated?`)가 붙은 크롭을 검수한다. 두 줄이 같이 잘렸거나 날짜가 잘린 크롭은 `train_list.txt`/`val_list.txt` 에서 그 줄을 지운다. 시트는 플래그 → 편집거리 큰 순이라 앞 1~2장만 보면 된다.
- 라벨 텍스트는 포장에 찍힌 그대로(`2027.06.26`, `FEB/26/21`, `30 12 23`). 영문 월 대소문자는 라벨러가 본 대로.
- 3차 라벨(블록 11~15)이 들어오면 `--blocks` 에 추가해 다시 뽑는다. 라벨 CSV 는 git 에 있으므로 스크립트만 다시 돌리면 된다.
- `data/rec_train/` 은 용량이 커서 git 에 올리지 않는다 (`.gitignore` 에 `data/rec_train/` 추가할 것). zip 으로 묶어 Colab 에 올린다.

**바로 돌릴 노트북:** `notebooks/finetune_rec_colab.ipynb` 를 Colab 에 올리면 아래 1~4절이 셀로 들어 있다 (설정 yaml 자동 생성 포함). 아래는 그 노트북이 하는 일의 설명이다.

### 0-1. 도트매트릭스 합성 데이터 (9/11 추가)

미검출의 주원인이 잉크젯 도트 인쇄라 사전학습 인식기가 본 적 없는 글자 형태다. `python notebooks/make_synth_dotmatrix.py --n 3000 --out data/rec_synth` 로 5×7 점 격자 폰트 날짜를 실제 포장 사진 배경에 합성한 크롭 3,000장을 만든다(`sheet_01.jpg` 로 미리보기). 라벨 형식 분포는 실측을 따르고 EXP·BEST BEFORE·시각·로트 접두·접미도 섞는다. **train 에만 넣고 val 은 실제 크롭만** 유지한다. Colab 노트북에 합치는 셀이 있다 (`rec_synth.zip` 업로드).

## 2. 설정 파일

`configs/rec/PP-OCRv5/multi_language/en_PP-OCRv5_mobile_rec.yaml` 을 복사해 `configs/rec/itda_en_rec.yaml` 로 만들고 아래만 바꾼다.

```yaml
Global:
  epoch_num: 30                       # 기본 75. 데이터가 수백 장이라 30 으로 시작, val acc 가 정체하면 멈춤
  save_model_dir: ./output/itda_en_rec
  pretrained_model: ./en_PP-OCRv5_mobile_rec_pretrained.pdparams
  character_dict_path: ./ppocr/utils/dict/ppocrv5_en_dict.txt   # 그대로. 숫자·영문·구분자 전부 포함
  max_text_length: 25
  use_space_char: true
  eval_batch_step: [0, 100]           # 100 iter 마다 val
  save_epoch_step: 5
Optimizer:
  lr:
    learning_rate: 0.0001             # 기본 0.0005. 파인튜닝이라 1/5 로
Train:
  dataset:
    data_dir: ./train_data/rec_train/
    label_file_list: [./train_data/rec_train/train_list.txt]
  loader:
    batch_size_per_card: 32
Eval:
  dataset:
    data_dir: ./train_data/rec_train/
    label_file_list: [./train_data/rec_train/val_list.txt]
  loader:
    batch_size_per_card: 64
```

- `Train.dataset.name` 은 기본 `MultiScaleDataSet` 그대로 둔다 (증강 포함).
- 데이터가 적으면(<500) `epoch_num` 을 더 줄이고 `learning_rate` 를 0.00005 로. 과적합 징후 = train acc 만 오르고 val acc 정체.

## 4. 파이프라인에 넣기 (로컬)

1. `weights/en_PP-OCRv5_mobile_rec/` 를 백업하고, 내보낸 세 파일을 그 폴더에 덮어쓴다. `config.json` 은 기존 것을 그대로 둔다.
2. 오프라인 로드 확인: `ITDA_INPUT_DIR=./val_images jupyter nbconvert --execute predict.ipynb`.
3. **튜닝용 300장(블록 6·9·10)이 아니라 측정용 500장(블록 1~5)에서** `notebooks/eval.py` 로 전후 비교. val 블록 6 은 학습에 안 썼지만 같은 라벨러 분포라 500장 결과를 기준으로 채택 여부를 정한다.
4. 채택하면 `download_weights.sh` 가 공식 모델을 받는 부분을 우리 가중치(예: GitHub Release 첨부 또는 Google Drive 공개 링크)로 바꾼다. 채점 서버는 오프라인이므로 `weights/` 에 미리 들어 있어야 한다.

## 5. hard sample 2차 파인튜닝 (계획서 3.3)

1차 학습 모델로 803장을 다시 돌려 틀린 이미지만 `make_rec_dataset.py` 로 다시 뽑고(`manifest.csv` 의 dist>0 이 hard), 그것만으로 epoch 을 1차의 1/3 이하로 짧게 한 번 더 학습. 500장에서 확인.

## 함정

- Colab 의 CUDA 버전과 `paddlepaddle-gpu` 휠 인덱스가 맞아야 한다. 안 맞으면 `import paddle` 에서 죽는다. `!nvidia-smi` 로 확인.
- 학습 config 의 `character_dict_path` 와 export 된 `inference.yml` 의 사전이 같아야 추론 결과가 맞는다. 사전을 줄이려면(숫자·영문만) 학습 전에 바꾸고 export 까지 같은 파일을 써야 한다. 첫 시도는 기본 사전 그대로.
- 학습 라벨에 탭이나 줄바꿈이 들어가면 안 된다. `make_rec_dataset.py` 가 raw 의 태그 토큰을 떼고 한 줄로 쓴다.
- 700장 남짓으로는 큰 폭 상승을 기대하기 어렵다. 3차 라벨(2,000장+)이 들어오면 다시 뽑아 재학습하는 것이 본 게임이다.
